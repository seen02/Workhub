# 모든 참여자가 사용하는 진행 통계

2026-09-18 배포. 기존 관리자 전용 현황 화면을 **진행 통계** 탭으로 개편했다. Authentik 업무 사용자 그룹의 팀장·홍길동·김철수 모두 볼 수 있다. 프로젝트 관리·담당자 배정·주간 현황 발행 등 관리 작업은 계속 관리자 권한이다.

## 사용하는 흐름

1. 허브를 새로고침하고 왼쪽 **진행 통계**를 누른다. 기본은 **전체 프로젝트 / 전체 담당자 / 앞으로 7일**이다. 업무 보드의 프로젝트 선택과 독립적으로 비교한다.
2. 관리자는 첫 카드에서 **전체 프로젝트 진행률**을 확인한다. **프로젝트별 진행** 표에서는 프로젝트 진행률과 막대를 우선 비교하고, 완료 업무 수·완료 기준 달성률·기한 초과·마감 임박을 확인한다. 프로젝트 이름을 누르면 그 프로젝트로 좁혀지고 첫 카드는 **선택 프로젝트 진행률**로 바뀐다. 담당자를 선택하면 **참여 업무 기준 프로젝트 진행률**로 범위를 명시한다. 실무자의 첫 카드는 업무 완료율을 유지한다.
3. 실무자는 **내 담당 기준 보기**를 누른다. 본인이 참여하는 업무가 남고, 기준 달성률과 남은 기준 수는 본인 배정 항목만 집계된다. 담당자 표의 이름으로 다른 담당자도 선택할 수 있다.
4. 계획 범위를 **7일 / 14일 / 30일**로 바꾼다. **남은 업무의 마감 일정**에서 기한이 지난 업무·오늘·선택 범위 내 마감·그 이후·마감 미정을 확인한다.
5. 기한 초과·마감 임박·장애요인·마감 미정 카드를 누르면 **다음에 점검할 업무**의 해당 목록으로 이동한다. 업무명·프로젝트·담당자 검색도 가능하다.
6. 목록에서 마감까지 남은 날짜, 남은 기준, 장애요인, 다음 행동을 확인한다. 기준을 펼쳐 항목별 상태를 확인하고, **진행 보고**로 해당 프로젝트·업무가 선택된 보고 화면으로 이동한다. 편집 권한이 없는 업무에는 보고 버튼을 제공하지 않는다.
7. **지금 동기화**는 Outline 최신 상태를 읽는다. 일반 갱신은 약 20초마다 실행한다. 마지막 동기화 시각과 지연 여부를 표시한다.

업무의 다음 행동이 이미 작성돼 있으면 그대로 표시한다. 미기재인 경우에는 **점검 제안**이라고 구분해서 마감 재협의·장애요인 확인·마감일 설정 등의 안내를 제공한다. 통계 화면이 원본에 새로운 계획을 자동 저장하지는 않는다.

## 숫자의 의미

| 지표 | 계산 |
|---|---|
| 전체 프로젝트 진행률 (관리자) | 집계 가능한 프로젝트별 진행률의 단순평균. 프로젝트마다 동일 비중이며 빈 프로젝트·진행률 전부 미기재 프로젝트는 제외하고 집계/전체 개수를 표시 |
| 프로젝트 진행률 | 해당 프로젝트에서 진행률이 기재된 업무의 단순평균. 업무 보드의 프로젝트 진행률과 동일 |
| 업무 완료율 | 완료 상태인 업무 수 ÷ 유효 업무 수 |
| 평균 업무 진행 | 진행률이 기재된 업무의 단순평균. 미기재는 분모에서 제외하며 기재 건수도 표시 |
| 완료 기준 달성 | 완료된 기준 수 ÷ 전체 기준 수. 프로젝트별 퍼센트의 평균이 아님 |
| 기한 초과 | 한국 시간 오늘보다 마감일이 이전인 미완료 업무 |
| 마감 임박 | 오늘부터 선택한 7·14·30일 후까지 마감인 미완료 업무. 양 끝 날짜 포함 |
| 장애요인 | 장애요인 값이 있는 미완료 업무 |
| 마감 미정 | 유효한 마감일이 없는 미완료 업무 |
| 담당자별 남음 | 그 사람에게 배정된 예정·진행 중 기준 수 |

진행 중 기준에 임의의 부분 점수를 주지 않는다. 평균 업무 진행률은 업무 규모나 소요시간을 가중한 값이 아니다. 기준이 없거나 집계할 업무가 없으면 해당 비율은 **—**로 표시하며 0%로 단정하지 않는다. 백분율은 소수 첫째 자리까지 반올림하며, 6.25%는 6.3%로 표시한다.

담당자 필터의 업무 상태·마감은 **그 사람이 참여하는 업무 전체**를 기준으로 한다. 완료 기준 수·달성률만 본인 배정 항목으로 좁힌다. 예를 들어 본인 기준을 모두 끝냈어도 동료 기준이 남아 있으면 해당 업무 자체는 미완료다. 완료 기준의 기한은 현재 데이터 구조에 맞춰 부모 업무의 마감일을 따른다.

기한 초과와 장애요인 등의 카드 수는 중복될 수 있다. 일정 막대의 각 구간은 상호 배타적이므로 합계가 미완료 업무 수와 같다. 담당자별 항목 개수는 소요시간 또는 업무 난이도에 대한 평가가 아니다.

## 권한과 데이터

- `/api/analytics`, 기존 `/api/stats`는 인증된 업무 사용자에게 열었다. 미인증 접근은 거부한다.
- 현재 허브의 연결 프로젝트는 업무 사용자 그룹의 공동 열람 공간이다. 해당 그룹의 구성원은 연결된 프로젝트의 통계를 열람하고 담당자 필터로 본인 참여 범위를 좁힐 수 있다.
- 연결되지 않은 컬렉션·연결 해제된 프로젝트·일반 문서는 제외한다. 문서 ID별 최신 상태를 한 건으로 세며 보고 횟수나 개인 초안을 성과로 세지 않는다.
- 형식 오류 업무는 유효 집계 분모에서 제외하고 **집계 기준과 데이터 점검**에 원본 링크와 오류를 표시한다. 완료 기준 없음·진행률 미기재 수도 공개한다.
- 원본 보고·배정·확정 권한은 바꾸지 않았다. 주간 현황 초안과 발행은 관리자만 가능하고 프로젝트 하나를 선택한 경우에만 버튼이 활성화된다.
- 자동 갱신 실패 시 마지막으로 확인한 통계 화면을 유지하면서 실패 안내를 표시한다. 최초 조회·필터 변경 실패 시에는 잘못된 범위를 표시하지 않도록 통계 내용을 숨긴다. 원본 동기화가 실패하거나 2분 이상 지연되면 마지막으로 확인한 상태임을 표시한다.

## 구현과 검증

- `src/workhub/analytics.py`: 원본 스냅샷 기반 집계·계획 목록. 읽기 전용 계산이며 기존 업무 문서나 배정은 수정하지 않는다.
- `src/workhub/static/analytics.js`, `analytics.css`: 독립 필터, 프로젝트 비교, 담당자별 기준, 일정 막대, 점검 목록, 보고 바로가기, 모바일 화면.
- `src/workhub/main.py`: 업무 그룹 사용자 통계 조회 허용. 관리자 전용 관리·발행 API는 유지.
- `test_analytics.py`: 가중 기준 집계, 중복 문서, 기한 경계, 담당자 필터, 미기재/빈 데이터, 형식 오류, 우선순위, 권한, 반올림을 검사.
- `ops/verify_analytics.mjs`: 실제 Authentik 세 계정으로 API와 브라우저 UI 검증. 기존 업무·프로젝트를 만들거나 지우지 않으며 검증 전후 원문이 동일한지 비교한다.

전체 회귀 **87개 통과**. 마지막 반올림 보완 후 관련 집계·권한 테스트 **12개 재확인**. 실제 계정과 브라우저 확인 **43개 통과**(기본 통합 41개 + 담당자 문구·갱신 유지 2개). 데스크톱과 390px 모바일, 필터·목록 이동·보고 바로가기·실무자 공개·관리자 발행 제한을 확인했다. 자동 갱신이나 수동 동기화 후에도 사용자가 펼친 완료 기준 목록을 유지한다. 빈 데이터와 일시 오류 화면은 브라우저 읽기 응답만 격리해 모의 검증했다.

실제 데이터 검증 시점에는 업무 **4개**, 완료 기준 **11개 중 1개 완료(9.1%)**, 남은 기준 **10개**, 마감 미정 **1개**였다. 이 수치는 검증 시점의 스냅샷이며 보고·프로젝트 연결 변경에 따라 바뀐다. 테스트를 위해 원본 진행 상태를 꾸미거나 초기화하지 않았다.

## 프로젝트 중심 지표 및 조용한 자동 갱신 보완 (2026-09-18)

관리자 첫 지표는 업무 완료율 대신 전체/선택 프로젝트 진행률로 변경했다. 예를 들어 업무 수가 다른 두 프로젝트의 진행률이 100%, 20%이면 전체 프로젝트 진행률은 60%다. 프로젝트 안의 업무별 비중과 프로젝트 사이의 비중은 각각 동일하며 소요시간 가중치는 적용하지 않는다. 기준 설명은 화면의 **집계 기준과 데이터 점검**에서도 확인할 수 있다.

20초 자동 갱신은 유지한다. 화면 전체의 반투명 처리, 보드 진행률 숨김, 변경 없는 DOM 재생성을 제거했다. 같은 내용은 기존 노드를 유지하므로 스크롤·키보드 포커스·펼친 기준이 유지된다. 통계 탭에서는 통계만 조회하며 중첩 자동 요청과 브라우저 백그라운드 탭의 불필요한 갱신을 건너뛴다. 갱신 시각과 변경된 데이터는 계속 반영된다.

추가 집계·권한 테스트 **14개**, 기존 실제 세 계정 통계 검증 **41개**, 새 브라우저 검증 **6개 묶음** 통과. 새 검증은 실제 20초 주기 두 번(보드/통계), 화면 밝기·DOM 동일성·포커스·스크롤·펼침 유지, 자동 조회 오류와 복구, 변경된 진행률 반영, 프로젝트 필터, 모바일 넘침을 확인한다. 오류·수치 변경은 브라우저 읽기 응답만 모의 처리했으며 원본 문서는 변경하지 않았다.

검증 스크립트: `ops/verify_quiet_refresh.mjs`. 결과: `reports/quiet-refresh-verification.json`. 화면: `reports/admin-project-progress.png`, `reports/admin-project-progress-mobile.png`.
