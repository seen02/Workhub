# 프로젝트 연결 해제

2026-09-18 구현. **프로젝트 관리**에서 새 프로젝트 연결과 현재 등록된 프로젝트의 연결 해제를 함께 처리한다. 연결 해제는 관리자만 가능하며 **컬렉션을 삭제하는 기능·옵션은 없다.**

## 사용 방법

1. 허브의 **프로젝트 관리**를 연다.
2. **현재 연결된 프로젝트**에서 대상의 **연결 해제**를 누른다.
3. 기본 버튼 **연결만 해제**를 누르면 Outline 문서에 변경 없이 허브 연결만 제거된다.
4. 업무 문서도 정리하려면 **업무 목록과 그 아래 모든 문서도 휴지통으로 이동**을 직접 체크한다. 대상 문서 이름과 하위 문서 전체가 삭제된다는 안내를 확인한 뒤 **문서 삭제 후 연결 해제**를 누른다.

삭제 옵션은 화면을 열 때마다 꺼진다. 실제로 연결된 업무 목록 ID와 현재 위치를 확인할 수 없으면 삭제 옵션을 비활성화하고 연결 해제만 제공한다. 상위 문서가 이름 변경된 경우에도 실제 문서 이름을 표시한다.

## 결과와 보존 범위

| 항목 | 연결만 해제 (기본) | 문서 삭제 후 연결 해제 |
|---|---|---|
| Outline 컬렉션 | 유지 | 유지 |
| 업무 목록 문서 | 유지 | 휴지통 이동 |
| 업무 목록 아래의 업무·하위 자료 | 유지 | 함께 휴지통 이동 |
| 업무 목록 밖의 요구사항·PRD 등 | 유지 | 유지 |
| 기존 Outline 접근 권한 | 유지 | 유지 |
| 허브 프로젝트·업무·통계 및 봇 선택 목록 | 제외 | 제외 |

허브에 보관한 과거 보고 초안과 관측 이력은 삭제하지 않는다. 연결되지 않은 컬렉션의 이력은 진행 통계 집계에서 제외한다. 연결 해제 전에 만든 미확정 초안은 해당 프로젝트가 해제된 동안 확정할 수 없지만 취소는 가능하다. 봇의 현재 업무 선택도 해제해 잘못된 프로젝트에 후속 보고가 들어가지 않도록 한다. 이미 열어 둔 다른 허브 화면은 다음 주기 갱신 또는 새로고침 시 프로젝트 선택을 갱신한다.

재연결은 **프로젝트 관리 → 기존 컬렉션 선택 → 프로젝트 연결**로 한다. 기본 연결 해제였다면 기존 문서 ID·업무·업무 목록을 그대로 사용한다. 업무 목록을 삭제했다면 첫 새 업무 등록 시 새 업무 목록을 만든다. 휴지통에 있는 이전 업무가 자동으로 복구되는 것은 아니다.

## 구현

- `outline.unlink_preview`: 관리자 권한 및 등록 프로젝트 확인, 저장된 업무 목록 ID와 실제 문서 위치 검사. 문서를 새로 만들거나 이름으로 임의 선택하지 않는다.
- `outline.unlink_project`: 기본값은 `delete_task_list=False`. 레지스트리 제거, 업무 캐시 비활성화, 선택 중인 봇 문맥 해제를 한 DB 트랜잭션으로 처리한다.
- 선택 삭제는 확인된 업무 목록에만 `documents.delete`를 `permanent=False`로 호출한다. **컬렉션 삭제 API를 호출하지 않는다.** 다른 문서 ID를 전달하거나 문서 위치가 변경되면 삭제를 거부한다.
- 삭제 요청의 처리 의도를 먼저 기록해 응답 유실 시 재시도할 수 있다. 삭제 실패 시 프로젝트 연결을 유지한다. 완료된 요청을 재전송해도 재연결한 프로젝트를 다시 끊지 않는다.
- `POST /api/projects/{collection_id}/unlink`: Authentik 세션, 관리자 권한, Origin 및 CSRF 검사. `delete_collection` 같은 정의되지 않은 입력 필드는 거부한다.
- 업무 조회·현황 이력은 연결된 프로젝트만 대상으로 한다. 마지막 프로젝트까지 해제해도 기본 컬렉션을 자동 재연결하지 않는다. 빈 화면에서도 프로젝트 관리로 새 연결이 가능하다.

## 검증

배포 버전의 자동 테스트 **75개 통과**, 실제 계정·브라우저 검증 **25개 통과**. 컬렉션 삭제 옵션 거부, 기본 문서 보존, 선택한 업무 목록·하위 문서의 휴지통 이동, PRD 보존, 재연결, 봇 목록 제외를 확인했다. 기존 사용자 프로젝트 연결과 업무 본문도 동일했다.

자동 테스트 결과: `reports/unlink-unit-tests.txt`.

실제 계정과 브라우저 검증: `ops/verify_unlink.mjs`, 결과 `reports/unlink-verification.json`.
관리자 화면에서 기본 해제·재연결·삭제 선택 해제를 실행하고, 컬렉션·PRD 보존, 휴지통의 하위 문서, 통계 제외, 이전 초안 확정 차단, 봇 목록 제외, 직원 권한 거부와 CSRF를 확인한다. 기존 사용자 프로젝트와 업무가 그대로인지 비교한다. 마지막 프로젝트를 해제한 빈 화면은 실제 프로젝트를 건드리지 않고 브라우저의 목록 응답을 비운 별도 UI 검사로 확인한다.

화면 증거: `reports/project-management-unlink.png`, `reports/unlink-default.png`, `reports/unlink-delete-option.png`.

검증용으로 만든 **[검증] 연결 해제 …** 컬렉션은 연결 해제한 상태로 Outline에 남긴다. 컬렉션 보존을 확인하기 위해 삭제하지 않으며, 그 안의 PRD 문서도 유지한다. 검증용 업무 목록과 하위 업무만 휴지통으로 이동했다. 컬렉션 ID와 PRD 링크는 실제 검증 결과 파일에 기록한다.
