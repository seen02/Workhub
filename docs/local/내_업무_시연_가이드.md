# ‘내 업무’ 조회 → 실행 → 보고 시연 가이드

2026-09-30 로컬 실행 서비스 적용·검증 완료. 별도 서버 전달용 배포 묶음에는 아직 포함하지 않았다.

## 1. 준비된 시연 환경

- 채팅: [Rocket.Chat](http://rocketchat.workhub.test)
- 사용 계정: **팀장 (`admin@example.com`)**. 기존 Authentik 로그인 방법을 사용한다. 브라우저 확인 당시 이 계정으로 로그인되어 있었다.
- 대화 상대: **통합 업무 비서** 개인 대화방. 채널이나 일반 업무보고 방에 명령을 보내는 방식이 아니다.
- 새 시연 프로젝트: **내 업무 시연 서비스**, **내 업무 시연 운영**.
- 보고 전송 대상: 비공개 **my-tasks-demo-20260930**. 시연 계정과 업무 비서만 참여한다.
- 기존 실제 업무는 수정하지 않았다. 새 시연 업무는 초기 상태로 준비되어 있다. 검증 보고 한 건은 시연방과 해당 문서 이력에 남아 있다.

처음 조회하면 기존 본인 업무와 새 시연 업무가 함께 나온다. 검증 시점에는 11개 프로젝트에서 6건이 표시되었다. 기존 업무가 변경되면 전체 건수는 달라질 수 있다.

## 2. 5~10분 시연 순서

### ① 프로젝트 선택 없이 전체 업무 확인

통합 업무 비서 개인 대화방에서 다음을 입력한다.

```text
내 업무
```

기대 결과:

- 오늘 날짜와 전체 할 일 수가 먼저 나온다.
- 기한 초과 / 오늘 마감 / 예정 / 마감일 미정 건수가 한 줄로 표시된다.
- 업무에는 프로젝트명, 제목, 마감일, 상태, 내 완료 기준이 표시된다.
- 검증 당시 전체는 **6건**, 분류별로 **1 / 1 / 2 / 2건**이었다.

소개 멘트: “프로젝트마다 들어가서 찾지 않고, 지금 내가 해야 할 일을 한 번에 확인합니다.”

### ② 마감일이 지난 업무를 따로 확인

기한 초과만 따로 확인하려면 다음 명령을 입력한다.

```text
내 업무 기한 초과
```

**[내 업무 시연 서비스] 로그인 화면 수정**이 표시된다. 9월 30일 기준 마감일은 9월 28일이며 **2일 초과**다.

확인할 내용:

- 기한 초과 업무만 본문에 나타난다. 위의 전체 분류별 건수는 계속 보인다.
- 내 완료 기준은 **1/3 완료**이고, 남은 ‘오류 안내 문구 적용’과 ‘모바일 화면 확인’이 표시된다.
- 원문의 상태가 단순히 ‘진행 중’이어도 날짜가 지났으면 기한 초과로 분류된다.

### ③ 업무 상세에서 완료 기준 전체 확인

**로그인 화면 수정 · 상세** 버튼을 누른다. 목록에서 `1`을 입력해도 된다.

상세의 기대 결과:

| 내 완료 기준 | 상태 |
|---|---|
| 화면 배치 수정 | 완료 ☑ |
| 오류 안내 문구 적용 | 진행 중 ☐ |
| 모바일 화면 확인 | 예정 ☐ |

**Outline 원문 열기**를 누르면 해당 업무 문서가 열린다. 업무 대표 담당자나 업무 전체 상태와 ‘내 기준’의 완료 상태를 구분해서 볼 수 있다.

소개 멘트: “업무 이름만 보는 게 아니라, 무엇을 어디까지 해야 끝나는지 확인합니다.”

### ④ 앞으로 할 일과 마감일 미정 업무 확인

`내 업무 예정`을 입력하면 **[내 업무 시연 운영] 검색 결과 개선**을 확인할 수 있다.

- 업무 마감은 10월 2일이다.
- 업무 대표 담당자는 다른 사람이어도, 팀장에게 ‘검색 결과 표시 구현’ 기준이 배정되어 있어 개인 목록에 나온다.
- 다른 담당자의 ‘서버 검색 검증’은 팀장의 개인 완료 기준 목록에 섞이지 않는다.

이어서 `내 업무 마감일 미정`을 입력한다.

- **운영 체크리스트 작성**이 표시된다.
- 마감일과 완료 기준이 없는 업무도 누락되지 않으며 **마감일 미정 / 완료 기준 미등록**으로 표시된다.
- 목록에 있는 기존 ‘점검 업무’도 본인의 남은 기준이 있어 함께 표시될 수 있다.

소개 멘트: “마감일이 없어도 해야 할 일을 놓치지 않고, 공동 업무는 내가 맡은 부분만 확인합니다.”

### ⑤ 작업 결과 보고

개인 대화방에 다음을 입력한다.

```text
보고
```

보고 안내가 나오면 아래 문장을 그대로 보낸다. 실제 검증에 사용한 업무·기준 표현이다.

```text
내 업무 시연 서비스 프로젝트의 안내 문서 정리 업무에서 안내 문서 검토 및 공유 완료
```

초안에서 다음 세 가지를 확인한다.

1. 프로젝트: **내 업무 시연 서비스**
2. 업무: **안내 문서 정리**
3. 완료 기준: **안내 문서 검토 및 공유 — 완료**

**보고 및 반영**을 누르고 **my-tasks-demo-20260930**을 선택한다. 이 방을 선택하면 보고 게시와 문서 반영이 실제 실행된다.

기대 결과:

- 시연방에 보고가 게시된다.
- ‘업무 1건을 저장했어요’ 안내가 나온다.
- Outline 문서의 해당 완료 기준이 완료로 바뀐다.

다른 실제 업무보고 채널을 선택하지 않아도 이 전용 방에서 모든 흐름을 확인할 수 있다.

### ⑥ 최신 내 업무 재조회

보고 결과의 **내 업무 다시 보기** 버튼을 누르거나 `내 업무`를 다시 입력한다.

기대 결과:

- **안내 문서 정리**가 남은 할 일에서 빠진다.
- 다른 업무에 변화가 없다면 전체 **6건 → 5건**, 오늘 마감 **1건 → 0건**으로 바뀐다.
- 기한 초과 업무와 마감일 미정 업무는 그대로 남는다.
- 보고 초안만 만들었거나 채팅 게시만 끝나고 문서 저장이 실패한 경우에는 완료로 사라지지 않는다.

소개 멘트: “아침에 내 업무를 확인하고, 실행한 뒤 보고하면 다음 조회에 최신 상태가 반영됩니다.”

## 3. 알아두면 좋은 조작

| 입력·버튼 | 기능 |
|---|---|
| `내 업무` | 전체 프로젝트의 남은 본인 업무 |
| `내 업무 기한 초과` | 마감일이 지난 본인 업무 |
| `내 업무 오늘 마감` | 오늘 마감 업무 |
| `내 업무 예정` | 앞으로 마감인 업무 |
| `내 업무 마감일 미정` | 마감일이 없는 업무 |
| 업무 이름의 상세 버튼 / 현재 목록의 번호 | 본인의 완료된 기준까지 포함한 상세 |
| 더보기 | 목록 바로 아래에서 다음 업무 8건 또는 다음 완료 기준 8개 확인. 마지막에는 표시되지 않음 |
| `내 업무` 재입력 | 전체 목록을 새로 조회 |
| `보고 현황` | 기존 보고를 다시 확인 |
| `업무` / `현재 업무` | 기존 프로젝트별 보고 업무 선택 / 선택 업무 확인 |

분류·새로고침·보고 현황 이동 버튼은 제거했다. 더 볼 내용이 있으면 남은 개수와 **더보기**가 목록 바로 아래에 표시된다. 업무별 상세 버튼은 유지한다. 조회 자체로 작성 중인 보고 초안은 바뀌지 않는다. 다만 숫자는 항상 가장 최근에 열린 목록 기준이다. 이전 화면 버튼이나 30분 지난 버튼은 최신 목록으로 안내하므로, 시연 중에는 최신 봇 메시지의 버튼을 사용한다.

‘내 업무’에 표시되지 않는 시연 사례도 3개 준비했다: **이미 완료한 업무**, **다른 담당자 전용 업무**, **공동 업무 완료 구분**. 마지막 업무는 다른 담당자의 일이 남아 있어도 팀장의 기준은 완료했으므로 팀장의 할 일에서 빠지는 사례다.

## 4. 다른 날 다시 시연하거나 처음 상태로 되돌리기

PowerShell에서 다음을 실행한다. 저장된 시연 문서 ID 7개만 대상으로 날짜와 완료 상태를 초기화한다. 실제 업무는 변경하지 않으며 기존 시연 보고 이력은 남긴다.

```powershell
Set-Location -LiteralPath '<workspace>'
docker compose run --rm --no-deps -v './ops:/app/test-ops:ro' --entrypoint python workhub /app/test-ops/verify_my_tasks_live.py reset
```

성공하면 `demo_reset: true`, 현재 날짜, `tasks: 7`이 출력된다. 이후 채팅에서 `내 업무`를 다시 입력한다.

- 로그인 화면 수정: 실행일보다 2일 전 마감
- 안내 문서 정리: 실행일 당일 마감
- 검색 결과 개선: 실행일보다 2일 뒤 마감
- 운영 체크리스트 작성: 계속 마감일 미정

시연 업무의 제목·소속·완료 기준 개수를 임의로 변경했다면 초기화 도구가 중단될 수 있다. 그 경우 해당 시연 문서를 직접 확인한다.

## 5. 검증 결과와 현재 한계

- 전체 자동 테스트 **308개 통과**. 신규 개인 업무 관련 테스트 27개 포함.
- 실제 11개 프로젝트 조회, 본인/타인/공동 업무 구분, 원문 무변경 확인.
- 실제 비공개 시연방 보고 → 문서 반영 → 완료 업무 제외 → 시연 상태 복원 확인.
- 실제 Rocket.Chat에서 기한 초과·상세·미정 필터와 좁은/데스크톱 폭 확인.
- 원문 조회만 측정한 사례는 **3.1초**, SSO·조회·채팅 전송을 포함한 실제 봇 처리는 **약 4.7~14.7초**였다. 보고 처리와 함께 실행하면 더 기다릴 수 있으므로 명령을 연속해서 여러 번 보내기보다 결과를 기다린다.
- 기능 자체는 AI나 RAG를 호출하지 않는다. 기존 `보고` 흐름은 기존 AI 처리와 대기 정책을 따른다.
- 일일 계획표 저장·자동 우선순위 추천·알림 예약은 이번 기능에 포함하지 않는다.

자동 테스트 재현:

```powershell
docker compose run --rm --no-deps -v './src/workhub:/app/workhub:ro' -v './ops:/app/test-ops:ro' --entrypoint python workhub /app/test-ops/run_workhub_tests.py
```

실제 업무 조회 검증(조회만 수행):

```powershell
docker compose run --rm --no-deps -v './ops:/app/test-ops:ro' --entrypoint python workhub /app/test-ops/verify_my_tasks_live.py check
```

전체 검증 근거와 소스 적용 기록은 [구현 계획의 완료 기록](내_업무_조회_구현_계획.md#9-구현검증-완료-기록--2026-09-30)을 참고한다.
