# RAG 구현·검증 결과

작성일: 2026-09-16. 초기 RAG 구현·검증 기록이다. 현재 통합 환경은 [프로젝트 README](../../OVERVIEW.md)와 권한 구현 결과를 기준으로 한다.

## 적용한 변경

| 영역 | 구현 결과 |
|---|---|
| 답변 정확성 | 문서 수·출처·범위는 서버가 표시한다. 모델 출력은 연결된 원문의 전체 단위와 대조하며 상태·조건·담당자·숫자가 바뀌면 원문 발췌로 대체한다. 현재 본문·인용·예시 구분과 상태 충돌 안내를 추가했다. |
| 사전 검색 | 별도 PostgreSQL 17 + pgvector에 문서·조각·활성 버전·프로필·동기화 상태를 저장한다. 문자열/pg_trgm과 exact cosine 후보를 RRF로 결합하고 중복·과도한 한 문서 집중을 줄인다. 프로젝트 코드는 명시적 필터로 적용한다. |
| 동기화·접근 | 기본 5분 변경 감지, 저장 후 동기화 신호, 완전한 목록에서 삭제 감지, 403/404·보관·이동 제외, 원문 버전 재확인을 적용했다. 새 조각 전체를 준비한 뒤 트랜잭션으로 교체한다. 캐시와 후속 질문도 재확인한다. |
| 4K 관리 | `app.llm` 공통 입력 검사, 고정 Qwen tokenizer, schema·메시지 형식 비용, 출력 상한과 496토큰 여유를 포함한다. 긴 결과는 기존 event ID 조회 방식으로 화면에 표시한다. |
| 전체 조사 | 빠른 검색과 구분한다. 문서 목록 확정 → 순차 읽기 → 문서마다 체크포인트 저장. 기본 10개/120초 한도를 넘으면 부분 결과와 남은 목록을 보존한다. “조사 이어서”로 같은 기록을 사용한다. |
| 취소·복구 | 실행 전 등록, 작업별 실제 asyncio 취소, 대기/실행/부분 완료/실패/취소/재시작 중단 상태, 부분 결과 보존을 추가했다. 읽기는 전체 실행 잠금에서 분리하고 모델 호출만 직렬화한다. 기존 저장 UUID 검증을 유지했다. |
| WebUI | 도구·필터를 실제 등록했다. 중지 시 백엔드 취소와 동일 대화 메시지의 부분 결과 저장을 연결했다. 개발 화면에도 진행·중지·RAG 상태·동기화 기능을 추가했다. 시작·종료 스크립트에 RAG 서비스를 반영했다. |

기존 Outline DB 이미지·스키마·볼륨과 Qwen 답변 모델은 유지했다. 실제 업무 문서는 덮어쓰지 않았다. 실제 Outline 쓰기는 `로컬 AI 테스트`의 `[RAG 검증]` 가상 근거 3개와 템플릿 메모 1개에 한정했다. 같은 메모 저장 재시도는 같은 문서 ID를 반환했다.

E5의 `query:`/`passage:` 접두사, 정규화, 최대 512토큰을 적용했다. 긴 단위는 명시적으로 분할하고 분할 여부를 기록한다. exact cosine과 트랜잭션은 [pgvector 공식 문서](https://github.com/pgvector/pgvector)를 기준으로 구현했다.

실사용 중 발견한 두 문제도 수정했다. 프로젝트 코드가 의미 검색을 과도하게 지배하던 부분은 SQL 범위 필터와 질문 의미를 분리했다. “컬렉션의 문서를 모두 읽어줘”를 목록 조회로 오해하던 경우에는 명시적인 전체 읽기 의도를 우선한다. WebUI inlet의 화면 이벤트가 항상 DB에 저장되지는 않아, 소유자를 확인한 동일 대화 메시지에 체크포인트를 저장하도록 보완했다.

## 응답 시간과 자원

단일 PC의 작은 표본이며 처리 시간 보장이 아니다. Qwen이 로드된 상태의 백엔드 5회는 **1.94~10.13초**, 강제로 모델을 내린 뒤 첫 질문 1회는 **19.07초**(모델 로딩 8.97초 포함)였다. 재로딩 후 생성 속도가 달라져 범위를 그대로 보고한다. WebUI 최종 읽기 시험은 검색 16.2초, 후속 12.1초 각 1회이며, 요청 해석·폴링·최종 화면 처리까지 포함해 백엔드와 측정 구간이 다르다.

최종 빠른 백엔드 질문 예: 범위 확인 0.043초, 임베딩 0.069초, DB 검색 0.035초, 원문 확인 0.032초, Qwen 생성·로딩 18.525초. 단계별 값은 위 JSON에 보관했다. 전체 값에는 기타 처리·전송 비용도 포함한다.

WSL 설정은 **6GB를 유지**했다. 관측한 새 서비스 메모리는 임베딩 약 **0.48~1.03GiB**, 검색 DB 약 **47~52MiB**였으며, 전체 부하의 엄밀한 최대치 측정은 아니다. 한 시점의 WSL `MemAvailable`은 약 2.4GiB, swap 사용은 약 1.1GiB였다. 테스트에서 OOM은 확인되지 않았고, 메모리 증설·WSL 종료는 하지 않았다. 대규모 자료와 장시간 동시 부하는 별도 평가가 필요하다.

## 남은 제한

- 정확성 검증은 보수적인 **원문 발췌** 중심이다. 자연스러운 재서술이나 복잡한 추론의 의미적 정확성을 보장하지 않는다. 모델의 사실 변경을 허용하지 않는 대신 표현이 원문에 가깝다.
- 고정 검색 평가는 20문서·정답 질문 5개뿐이다. 선별 점수는 초기 기준이며 실제 업무 전체의 한국어 검색 품질을 보증하지 않는다. 일부 조건 질문에 추가 관련 후보가 포함될 수 있다.
- OCR·Outline 첨부 전체 색인·새 사용자 화면·사내 사용자별 Authentik/Outline 권한 매핑은 구현 범위에서 제외했다. 현재는 API 키 하나의 권한으로 동작하는 개인 시험판이다.
- 임베딩 한도를 넘는 긴 단위는 나눠 저장하지만, 불완전한 문장으로 결론을 만들지 않도록 분할된 조각은 빠른 답변에서 제외한다. 해당 자료는 전체 읽기 경로로 확인할 수 있다. 구조 분할과 겹침·재조립 품질은 추가 개선 여지가 있다.
- 전체 조사 요약은 토큰 예산에 맞춘 짧은 근거이며, 나머지 읽은 근거는 펼쳐 보기와 서버에 남긴다. 10문서/120초 이후에는 이어 하기가 필요하다.
- tokenizer는 같은 Qwen 배포 계열의 파일과 보수적인 형식 비용으로 계산한다. 실제 Ollama `prompt_eval_count`와 비교한 3개 경계 시험에서는 초과가 없었지만, 미래 모델·chat template 변경 시 다시 검증해야 한다.
- 취소는 진행 중인 HTTP를 닫고 다음 처리를 중단한다. CPU 임베딩은 이미 실행한 작은 batch가 반환된 뒤 중단 확인하므로 그 batch를 OS 수준에서 강제로 종료하지 않는다.
- PostgreSQL 마이그레이션·런타임 계정은 현재 로컬 전용 계정을 공용으로 사용한다. 조직 공유 전에 최소 권한 계정 분리와 운영 보안을 추가해야 한다.
