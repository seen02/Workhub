# Workhub 화면 디자인 기준

화면 디자인 기준과 변경 사항을 이 문서에 유지한다. 중복된 과거 화면 개선 보고서는 정리했다.

## 방향

업무를 먼저 찾고, 상세에서 보고하고, 같은 흐름에서 처리 결과를 확인한다. 시연용 안내와 내부 시스템 용어보다 사용자가 해야 할 행동을 우선한다.

## 시각 기준

- 캔버스 #F6F7FB, 주요 작업 영역 #FFFFFF, 사이드바 #FBFBFD.
- 본문 #202630, 보조 글자 #647084, 구분선 #E5E7EF.
- 주요 버튼/진행 바 #4F5BD5, 선택 배경 #F0F1FF.
- 완료는 초록 + 문구, 기한 초과는 빨강 + 문구. 색상만으로 의미를 전달하지 않는다.
- Pretendard 우선 시스템 한글 글꼴. 통계 본문 15px, 마감 배지 15px, 보조 13–14px, 고정 지표 숫자 25px, 페이지 제목 24px. 좁은 화면에서는 핵심 지표를 줄여 배치하되 6개를 유지한다.
- 4/8/12/16/24/32px 간격. 버튼 모서리 8px, 주요 패널 10–12px.
- 장식 영문 소제목·대형 환영 배너·과한 그림자를 업무 화면에 추가하지 않는다.
- 주요 행동은 강조색, 취소·뒤로·보조 동작은 중립색. 삭제와 취소를 같은 의미로 표현하지 않는다.

## 화면 구조

- 상단 프로젝트 선택은 하나. 통계는 통계 내부 범위 선택기를 사용한다.
- 보드: 내 업무·팀 업무 제목 / 전체·미완료·마감초과·임박 빠른 필터 / 프로젝트 진행률 / 검색·정렬 / 8개씩 업무 목록 / 선택 업무 상세. 기본은 미완료·급한 업무부터. 사용법은 왼쪽 도움말에서 확인한다.
- 상세: 완료 기준과 담당자 / 다음 행동과 장애요인 / 결과물 / 보고·기준 배정 / 최근 기록.
- 보고: 업무 명시적 선택·작성 / 변경 요약과 기존 양식 / 결과·같은 업무로 복귀. AI 보고 정리와 상태만 변경을 분리한다. 문서 검색은 별도 내부 탭.
- 메뉴는 진행 통계 / 업무 보드 / AI 업무 비서 / 계정·인수인계 순서. 로그인 첫 화면은 통계다. 보고 초안과 계정 탭의 직접 링크는 유지한다.
- 통계: 낮은 상단 고정 지표 6개와 목차 / 전체 요약 / 프로젝트 진행 카드 / 약 3행 높이에서 스크롤하는 전체 점검 업무 / 담당자·마감 현황 / 계산 설명 / 프로젝트·담당자·7일·30일 조회 조건. ‘크게 보기’는 검색·체크리스트를 갖춘 우측 패널을 연다.
- 관리자는 통계에서 자신이 책임자인 프로젝트의 팀 전체, 업무 보드에서 선택 프로젝트의 팀 전체로 시작한다. 실무자는 본인 범위로 시작한다. 담당자 전환은 선택된 프로젝트·기간을 유지한다.
- 마감 기간은 완료 실적의 조회 기간이 아니다. 마감 임박 업무와 마감 일정 구간만 바꾸며 진행률 계산식은 유지한다.
- 통계 카드와 일정 숫자는 해당 업무를 확인하는 버튼이다. 펼친 체크리스트·입력한 검색어·선택 필터를 자동 갱신 중 유지한다.
- 보드의 프로젝트 전체 진행률과 통계의 개인 참여 범위를 명시적으로 구분한다.
- 업무 등록, 담당자 배정, 프로젝트 연결 관리와 현황 보고 기능을 보존한다.
- 시연 가이드는 왼쪽 아래 도움말에 둔다.

## 상태와 권한

- 초안과 원본 반영 결과를 구분한다. 저장 성공 후 목록 갱신 실패를 저장 실패로 표시하지 않는다.
- 저장 결과 불명확 상태에는 재확인을 제공한다.
- 화면 권한 표시는 서버 권한 검사를 보조한다. AI 출력으로 권한을 결정하지 않는다.
- 역할별 진행률 계산 공식과 기존 Rocket.Chat 보고문 양식을 디자인 변경 과정에서 바꾸지 않는다.
- 자동 갱신은 변경된 DOM을 갱신하며 입력·포커스·펼친 상세를 보존한다.
- 작성 메모의 페이지 내 임시 보존을 영구 자동 저장으로 설명하지 않는다.
- 키보드 포커스 표시를 유지하고, 좁은 화면에서는 업무 목록과 상세를 세로 배치한다.

## 2026-09-23 후속 개선

- 프로젝트별 고유 색을 카드·점검 목록에 동일하게 적용한다. 이름과 상태 문구를 함께 표시한다.
- 상단 목차에서 프로젝트·점검 업무·담당자별 남은 일·마감 일정·조회 조건으로 이동한다.
- 점검 목록은 전체 업무를 기본 제공하고 약 3행 높이 안에서 스크롤한다. 조건 버튼은 기본 목록을 바꾸며, ‘크게 보기’나 상단 지표를 누르면 우측 패널을 연다. 패널에서 5개 단위로 이동하며 자동 갱신 시 검색어·페이지·펼친 항목을 유지한다.

## 프로젝트 책임자와 업무 담당자

- 프로젝트 책임자는 Workhub 프로젝트 등록 정보로 별도 저장한다. 업무 담당자·체크리스트 담당자는 Outline 원본에 유지한다.
- 관리자 통계의 담당자별 남은 일은 개인 필터와 독립적으로 선택 프로젝트의 활성 구성원 전체를 표시한다. 미배정 인원도 포함한다.
- 프로젝트 책임자 지정으로 Outline 접근 권한을 부여하지 않는다.
- 최신 검증 보고: reports/project-managers-20260923.md (`reports/project-managers-20260923.md`; 로컬 자료).

## 2026-09-23 업무 흐름 개편

- 업무 보기·보고·자료 찾기는 왼쪽 메뉴와 업무별 보고 버튼으로 연결한다. 통계 위쪽에 메뉴를 반복하지 않는다.
- 실무자는 내 업무, 관리자는 팀 전체가 기본. 보드에서는 미완료를 먼저 보여주며 완료 업무는 전체/완료 필터로 확인한다.
- 비서에 직접 진입하면 업무 미선택이 기본. 보드의 보고 버튼으로 왔을 때만 대상을 지정한다.
- 입력과 초안 ID는 로그인 사용자별 sessionStorage에 임시 보관한다. 로그아웃·권한 회수 시 제거한다.
- 초안 생성 중 대상 선택과 중복 제출을 잠근다. 다른 화면으로 이동해도 응답이 강제로 화면을 바꾸지 않는다.
- 초안 계속하기, 입력 내용 수정, 취소 결과, 같은 업무 복귀를 제공한다. 내용 수정은 이전 초안을 취소한 후 새 초안을 만드는 흐름이다.
- 완료 기준이 있으면 등록 폼의 상태·진행률은 자동 계산한다. 기본 정보와 추가 정보를 구분한다.

## 2026-09-23 시각 디자인 개선

- Linear의 목록/상세 관계, Asana의 프로젝트 비교 화면, Notion의 문서 중심 화면을 참고했다. Workhub 고유 로고와 기능은 유지하며 아이콘은 코드로 작성했다.
- 셸은 아이콘 메뉴, 낮은 대비의 캔버스, 흰 작업 표면, 인디고 선택 상태를 사용한다. 페이지 제목 26px, 영역 제목 20–21px, 업무 제목 16px, 본문 14–15px를 기준으로 한다.
- 업무 목록은 하나의 흰 패널 안에 구분선으로 정리한다. 선택한 행은 옅은 배경과 왼쪽 강조선으로 표시하고 상세는 별도 패널로 구분한다.
- 보고는 밑줄 탭, 원형 단계 번호, 여백 있는 작성 영역을 사용한다. 긴 작성 안내는 작성 영역 아래의 접힌 도움말에 둔다.
- 통계는 6개 고정 지표, 프로젝트 색상, 하단 조회 조건을 유지한다. 프로젝트의 전면 그라디언트 대신 구분선과 진행 바에 색을 쓴다.
- 작은 통계 라벨은 진한 중립색으로, 키보드 포커스는 #4F5BD5로 표시한다. 모바일 라벨은 한글 단어가 중간에 끊기지 않도록 한다.

## 점검 업무 목록 최적화

- 늦은 업무·문제가 있는 업무·가까운 마감 순의 기존 정렬을 유지한다. 전체 업무를 바로 표시하여 기본 목록 탐색에 별도 버튼이 필요하지 않다.
- 기본 목록 높이는 PC 246px, 모바일 330px로 고정하고 내부 스크롤을 제공한다. 업무 수 증가나 필터 전환으로 하단 블록이 밀리지 않는다. 키보드 접근과 보이는 스크롤바, 전체 건수 안내를 제공한다.
- ‘크게 보기’는 모서리 확장 아이콘과 함께 표시하며 native dialog 우측 패널을 연다. 모바일에서는 화면 폭에 맞춘다. 제목·닫기·검색·페이지 이동은 목록 스크롤과 분리한다.
- 패널 검색은 대시보드 기본 목록에 영향을 주지 않는다. 필터 범위는 두 화면이 공유한다. 상단 지표 클릭은 해당 조건의 전체 패널을 바로 연다.
- Escape·닫기 시 원래 스크롤 위치와 실행 버튼 포커스로 복귀한다. 업무 확인·보고 이동은 조회 성공 후 패널을 닫고 이동한다.
- 권한 회수 시 열린 패널과 기본 목록의 업무 내용도 제거한다.

## 클릭 결과를 미리 알 수 있는 표시

- 내부 이동은 ‘상세 보기 →’, 외부 원문은 ‘↗’, 화면 확장은 모서리 아이콘 + ‘크게 보기’로 구별한다.
- 프로젝트 선택 시 ‘← 전체 프로젝트’를 상단 고정 영역의 왼쪽에 강조 표시한다. 프로젝트 범위만 해제하고 담당자·마감 기간은 유지한다.
- 점검 업무 패널은 닫기·ESC·바깥 배경 클릭으로 닫는다. 패널 내부에서 시작한 드래그는 닫기로 처리하지 않는다.
- 프로젝트·담당자 카드는 조회 범위를 좁힌다는 행동 문구와 선택 상태를 함께 표시한다. 통계 지표와 마감 구간에도 목록 진입 표시를 둔다.
- 접힌 설명·체크리스트·계정 설정은 꺾쇠 방향으로 상태를 표시한다. 같은 펼치기/접기 문구를 매번 반복하지 않는다.
- 보드의 목록·상세가 세로로 바뀌는 1240px 이하에서는 선택한 상세까지 이동한다.
- AI 예시는 ‘질문 넣기 / 문구 넣기’로 입력 보조임을 설명한다. 초안을 취소하는 수정과 Outline 반영을 실제 처리대로 이름 붙인다.

## 필요한 글만 남기는 원칙

- 페이지 제목과 버튼으로 이해되는 사용법 문장은 제거한다. 소개용 표어·동일 범위의 반복 설명·정상 갱신의 긴 안내를 추가하지 않는다.
- 기본 화면에는 업무명·진행률·담당자·마감·남은 항목·실행 버튼을 우선한다. 프로젝트 진행률과 체크리스트 완료율의 의미는 구분한다.
- 작성 예시·계산식·계정 운영 절차는 접힌 도움말 또는 시연 가이드에서 확인한다.
- 권한 거부·데이터 오류·미확정·저장 결과·취소 결과는 바로 표시한다. 간소화를 이유로 중요한 피드백을 숨기지 않는다.
- 참고: [Linear 목록의 표시 속성](https://linear.app/docs/display-options), [Notion 목록과 상세 열기](https://www.notion.com/help/views-filters-and-sorts). Workhub에 필요한 핵심 속성 노출과 목록/상세 분리 방식을 적용했다.

## 2026-09-28 통계 탐색과 완료 업무

- 점검 목록·우측 패널의 업무 상세는 새 탭 링크로 연다. 원래 통계 화면의 필터·검색·스크롤은 유지한다. 직접 링크는 프로젝트와 업무 ID로 열고 조회 권한을 다시 확인한다.
- 선택한 프로젝트 카드를 다시 누르면 프로젝트 선택을 해제한다. 전체 복귀 버튼은 프로젝트별 진행 상황 제목 옆에 둔다. 담당자·기간 조건은 유지한다.
- 상단 체크리스트 완료 지표 대신 완료한 업무 수를 보여주며, 누르면 완료 상태 업무의 검색 가능한 목록을 연다. 완료 기준 자체와 진행률 계산은 유지한다.
- ‘해결할 문제’는 ‘진행이 막힌 업무’로 표시한다. 장애요인이 기록된 미완료 업무이며 AI 자동 진단을 의미하지 않는다.

## 2026-09-28 프로젝트 선택과 지표 정리

- 업무 보드의 프로젝트는 이름순 버튼 그리드로 표시한다. 선택 색·체크·aria-pressed로 현재 프로젝트를 구분한다. 기존 프로젝트 권한과 전환 동작을 사용한다. AI 비서는 기존 드롭다운을 유지한다.
- 프로젝트 관리 버튼은 업무 등록과 같은 기본 강조색을 사용한다.
- 통계의 진행이 막힌 업무 KPI·일정 점검·필터·배지를 제거한다. 원본 장애요인 데이터와 업무 상세는 유지한다.
- 지표는 진행률 / 완료한 업무 / 마감 지난 업무 / 곧 마감할 업무 / 마감일 없는 업무의 5개다. 점검 목록은 기본 미완료 전체 뒤에 공통 네 항목을 같은 순서·이름으로 둔다.

### 2026-09-28 진행 통계 포트폴리오 구성
- 상단 6개 지표: 진행률, 완료, 미완료 전체, 마감 초과, 곧 마감, 마감일 없음. 업무 필터 순서 일치.
- 중복 요약 영역은 숨기고 프로젝트 비교 행, 점검 업무와 담당자 현황을 배치. 좁은 화면은 세로 배치.
- 담당자 현황은 체크리스트가 아닌 업무 수. 완료 / 마감 초과 / 그 외 미완료로 분리하여 중복 방지. 공동 업무는 해당 참여자마다 포함.
- 프로젝트 색상 표식·배지 통일. 기존 목차, 상세 새 탭, 프로젝트 재클릭 해제 및 전체 복귀 유지.
- 조회 조건은 하단 유지. 목록 내부 스크롤과 자동 갱신 상태 보존 유지.

### 2026-09-28 공통 UI 간결화
- 중복 제목·상태·날짜를 줄임. 점검 목록은 업무명/프로젝트/담당자/진행률/상대 마감만 표시하고 정확한 상태와 날짜는 상세에서 확인.
- 핵심 지표 명칭 단축, 업무 보드 중복 체크리스트 수 제거, AI 비서 작성/검토/완료 단계, 계정 화면 표와 인수인계 카드 정리.
- 공통 서체·간격·대비·키보드 포커스·모바일 조작 영역 개선. 모션 감소 설정 존중. 외부 의존성 추가 없음. 비표시 중복 요약 렌더 제거.
- 참고: https://atlassian.design/foundations/spacing , https://design-system.service.gov.uk/get-started/focus-states/

### 2026-09-28 지표에서 본문 목록으로 이동
완료/미완료/마감 지표 클릭 시 본문 점검 목록의 필터 선택 및 키보드 포커스 후 스크롤. 전체 진행률은 프로젝트 현황으로 이동. 사이드 패널은 크게 보기로 열기. 모션 감소 설정 존중, 건수 안내 높이 고정.

### 2026-09-28 마감 캘린더·담당자 분포
- 기본 주간(월~일), 월간 보기, 이전/다음/오늘 이동. 미완료 업무를 현재 프로젝트/담당자 조회 범위에서 표시.
- 프로젝트 색상, 업무명/담당자, 새 탭 상세. 주간 3개·월간 2개 초과 시 +N건으로 본문 날짜 필터 연결.
- 날짜 또는 분포 건수 클릭 시 본문 점검 목록에 기간/담당자 조건 추가. 일반 필터 클릭 시 일정 조건 해제.
- 분포는 업무 주 담당자 기준이며 공동 참여자별 중복 집계하지 않음. 주간은 일별, 월간은 주별. 해당 기간에 마감 업무가 있는 담당자만 표시. 건수는 소요 시간/난이도 아님.
- 마감 초과/기한 미정은 별도 버튼. 변경 없이 조회 전용. 외부 캘린더 라이브러리/API 없음.

### 2026-09-28 계획 기간 기반 일정 관리
- 마감일 점 표시에서 계획 시작일~마감일 기간 표시로 확장. 기본 업무 기간 타임라인, 주/월 달력은 기간에 겹치는 업무 표시.
- 담당자별 일일 동시 배정 수. 월간은 주별 최대 동시 건수, 기간 업무는 중복 없는 업무 수. 기간 미설정 업무는 별도 필터로 분리하고 임의 시작일 추정 금지.
- Outline 업무 문서의 선택적 시작일 필드. 기존 문서는 미정으로 읽고 최초 일정 변경 시 필드 삽입. 관리자 보드 상세 일정 조정 → 변경 검토 → 확정. 기존 보고/완료 기준 양식 유지.
- 기간은 계획이며 예상 시간/가용 시간에 따른 과부하 계산이 아님. 기간 내 주말도 포함. 담당자는 업무 주 담당자 기준.

### 2026-09-28 시작일 없는 기존 업무 표시 복구
일정 화면에서 기간 미설정 업무를 항상 펼친 목록으로 제공한다. 담당자, 프로젝트, 마감일과 상세 새 탭 링크를 표시하고 날짜를 추정하지 않는다. 기존 권한/담당자 범위를 따르며 권한 회수 시 목록도 제거한다.
