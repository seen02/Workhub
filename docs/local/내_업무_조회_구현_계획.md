# 통합 업무 비서 ‘내 업무’ 조회 구현 계획

작성일: 2026-09-30  
상태: 2026-09-30 구현·자동 테스트·실서비스 검증·로컬 실행 서비스 적용 완료  
최신 UI 변경: 아래 최초 계획의 분류·새로고침·보고 현황 이동 버튼은 사용자 요청으로 제거했다. 목록·완료 기준의 다음 페이지는 본문 바로 아래 **더보기**로 표시한다. 상세 내용은 문서 마지막 변경 기록을 따른다.  
목적: 개인 대화방에서 `내 업무`를 입력하면 참여 프로젝트에 걸친 본인의 할 일과 완료 기준을 확인하고, 실행 후 기존 `보고` 흐름으로 이어지게 한다.

## 1. 이번 구현의 범위

- 프로젝트를 먼저 고르지 않아도 전체 개인 업무를 조회한다.
- 기한 초과를 맨 위의 별도 구역으로 표시한다. 오늘 마감, 앞으로 할 업무, 마감일 미정도 구분한다.
- 업무마다 프로젝트, 업무명, 업무 상태, 마감일, 내가 맡은 완료 기준과 기준별 상태를 보여준다.
- 채팅에서 읽기 좋은 짧은 블록, 상세 보기, 분류별 보기, 페이지 이동, 새로고침을 제공한다.
- 조회 후 기존 보고를 작성하고, 실제 문서 반영이 끝나면 다시 조회하여 최신 상태를 확인한다.
- 이번에는 개인 일정표 저장, AI 자동 우선순위 추천, 알림 예약을 만들지 않는다. 조회 내용을 보고 사용자가 계획을 세울 수 있게 하는 단계다.
- 별도 보고 성능 개선 명세의 미착수 2~5단계를 이 기능의 선행 조건으로 삼지 않는다.

## 2. 실제 소스에서 확인한 출발점

| 위치 | 현재 동작과 구현 시 조치 |
|---|---|
| `src/workhub/bot.py`의 `handle` | `내 업무`가 `업무`와 같은 분기에서 선택 프로젝트의 보고 대상 목록을 연다. 새 전용 분기로 분리한다. |
| `src/workhub/report_chat.py`의 `route`, `INTRO` | 보고 명령과 버튼을 먼저 처리한다. 새 조회 명령·버튼이 보고문이나 초안 수정문으로 해석되지 않게 라우팅을 추가한다. |
| `src/workhub/chat_ui.py` | 버튼을 사용자·대화방과 실제 대상 ID에 연결하고, 숫자 선택·페이지 이동을 제공한다. 같은 이름의 다른 업무를 구분하는 기존 방식을 재사용한다. |
| `chat_ui.reportable` | 관리자는 전체 업무를 보고할 수 있다. 이것을 그대로 개인 업무 필터로 쓰면 타인 업무까지 표시되므로 별도 개인 담당 판정을 만든다. |
| `src/workhub/permissions.py` | 등록 프로젝트와 현재 Outline 직접·그룹·공개 접근 권한을 확인한다. 이 범위 안에서 담당 업무를 찾는다. |
| `src/workhub/outline.py` | `tasks`는 로컬 사본을 읽는다. `sync`는 전체 프로젝트를 순회하며 `normalize`를 통해 원문을 수정할 수 있다. 새 조회 경로에서 두 동작을 최신 원문 조회와 혼동하지 않는다. |
| `src/workhub/domain.py`, `criteria.py`, `human_tasks.py` | 업무 마감일·상태와 완료 기준별 담당자·상태를 파싱한다. 완료 기준 자체의 마감일은 현재 없다. 기존 형식과 사람이 작성하는 템플릿을 모두 지원한다. |
| `src/workhub/execution.py` | 요청 단위 권한·조회 재사용과 소요 시간 기록을 제공한다. 새 조회도 이 범위 안에서 실행한다. |

## 3. ‘내 업무’의 정확한 기준

### 조회 범위와 본인 판정

1. Rocket.Chat의 SSO 사용자 식별과 기존 개인 대화방 검사를 사용한다.
2. Workhub에 연결되어 있고 현재 읽을 수 있는 프로젝트를 검색 범위로 삼는다. 공개 프로젝트도 포함할 수 있지만 본인 배정 업무만 결과에 남긴다.
3. 완료 기준이 있는 업무는 **본인에게 배정된 미완료 기준이 하나 이상 있는 경우** 표시한다. 업무 대표 담당자가 다른 사람이어도 포함한다.
4. 완료 기준이 없는 업무는 **업무 담당자가 본인이고 업무 상태가 완료가 아닌 경우** 표시한다. `완료 기준 미등록`을 명시한다.
5. 완료 기준이 있는데 본인에게 배정된 기준이 없다면 대표 담당자여도 개인 실행 목록에는 넣지 않는다. 대표 담당자의 관리 현황은 기존 프로젝트 화면에서 확인한다.
6. 본인 기준을 모두 끝냈고 다른 사람만 작업 중이면 개인 할 일 목록에서 제외한다. 상세에서는 ‘내 완료 기준’과 ‘업무 전체 상태’를 구분한다.
7. 관리자도 본인 배정 기준으로 조회한다. 이름 문자열 유사도로 담당자를 추정하지 않고 기존 계정 매핑과 정규화된 담당자 정보를 사용한다.
8. 삭제·보관·미게시 문서, 연결 해제 프로젝트, 접근 권한이 없는 문서는 제외한다. 같은 문서 ID는 한 번만 집계한다.

### 날짜·완료·정렬

| 표시 구역 | 조건 | 정렬 |
|---|---|---|
| 🔴 기한 초과 | 업무 마감일 < 오늘, 내 할 일 남음 | 오래 지난 마감일 먼저 |
| 🟠 오늘 마감 | 업무 마감일 = 오늘, 내 할 일 남음 | 프로젝트명 → 업무명 → 문서 ID |
| 🔵 앞으로 할 업무 | 업무 마감일 > 오늘, 내 할 일 남음 | 가까운 마감일 먼저 |
| ⚪ 마감일 미정 | 마감일이 비어 있거나 `미정`, 내 할 일 남음 | 프로젝트명 → 업무명 → 문서 ID |

- 오늘은 요청 시작 시 `Asia/Seoul` 날짜로 한 번 계산한다. 날짜형 마감은 그날이 끝날 때까지 기한 초과가 아니다.
- 기한 초과 일수는 한국 날짜 차이로 계산한다. 업무 상태의 `지연` 표시는 날짜 기반 기한 초과 판정과 별개다.
- 보류 업무와 아직 시작일이 오지 않은 업무도 제외하지 않는다. 보류·시작 예정 정보를 함께 표시한다.
- 각 업무는 네 구역 중 하나에만 속한다. 완료 기준의 마감은 새로 만들거나 추정하지 않고 업무 마감일을 표시한다.
- 집계 단위는 고유 업무 문서 수다. ‘업무 4건’과 ‘남은 내 완료 기준 7개’를 혼용하지 않는다. 기준 없는 업무는 기준 개수에 가산하지 않는다.
- 읽을 수 없는 날짜, 해석 불가능한 담당자·기준은 `미정`이나 `0건`으로 둔갑시키지 않는다. 확인하지 못한 범위가 있음을 알린다.

## 4. 채팅 표시와 조작

기본 표시는 넓은 표 대신 업무별 짧은 블록이다. 아래는 실제 데이터가 아닌 화면 문구 예시다.

```text
내 업무 · 9월 30일 기준
참여 프로젝트에서 할 일 4건을 찾았어요.
기한 초과 1 · 오늘 마감 1 · 예정 1 · 마감일 미정 1

🔴 기한 초과 · 1건
1. [서비스 개선] 로그인 화면 수정
   마감 9/28 · 2일 초과 · 진행 중
   내 완료 기준: 1/3 완료
   • 오류 안내 문구 적용 — 진행 중
   • 모바일 화면 확인 — 예정

🟠 오늘 마감 · 1건
2. [고객 지원] 이용 안내 정리
   마감 오늘 · 진행 중
   • 안내 문서 검토 및 공유 — 진행 중

🔵 앞으로 할 업무 · 1건
3. [서비스 개선] 검색 결과 개선
   마감 10/2 · 미착수
   • 검색 결과 표시 구현 — 예정

⚪ 마감일 미정 · 1건
4. [운영 관리] 운영 체크리스트 작성
   마감일 미정 · 미착수
   • 점검 항목 작성 — 예정

업무를 누르면 완료 기준 전체를 볼 수 있어요.
작업한 내용은 ‘보고’로 알려 주세요.
9/30 09:20 조회
```

- 첫 메시지에서 전체 건수와 네 분류별 건수를 보여준다. 본문은 최대 8개 업무이며, 분류 순서를 유지한다.
- 한 업무에는 남은 내 기준을 최대 3개까지 미리 보여주고 `기준 N개 더 보기`로 상세에 연결한다. 완료된 내 기준은 개수로 요약하고 상세에서 체크 상태와 함께 전부 표시한다.
- 상세는 프로젝트·업무명, 업무 마감일, 전체 상태, 모든 내 기준, Outline 원문 링크를 제공한다. 다른 담당자의 기준은 개인 기준 목록에 섞지 않는다.
- 상세도 기준 개수·문자 수에 따라 나눠 표시한다. 마지막 기준과 버튼이 메시지 길이 제한으로 잘리지 않아야 한다.
- 업무 선택 버튼, `기한 초과`, `오늘 마감`, `예정`, `마감일 미정`, `전체`, `새로고침`, 필요할 때 `이전`·`다음`을 제공한다. 버튼 묶음은 별도 행으로 나누어 과밀하게 보이지 않게 한다.
- 분류 버튼으로 미래·미정 업무에 바로 접근할 수 있게 한다. 기한 초과가 많아도 뒤 분류를 반복 페이지 이동으로만 찾아야 하지 않게 한다.
- 현재 페이지/전체 페이지, 표시 범위/전체 건수, 조회 시각을 표시한다. 8건만 조회하고 전체처럼 말하지 않는다.
- 색상에만 의존하지 않고 ‘기한 초과’와 날짜를 글로 표시한다. 긴 제목·특수문자는 기존 텍스트 이스케이프를 사용한다.
- 완료 기준의 원문 의미를 AI로 요약하거나 바꾸지 않는다. 잘린 미리보기는 상세에서 원문 전체를 확인할 수 있어야 한다.

## 5. 조회 처리 구조

처리 순서: `명령 인식 → 본인·개인 대화방 확인 → 현재 접근 프로젝트 확인 → 원문 업무 수집 → 내 담당 판정 → 날짜별 분류 → 채팅 출력`.

### 원문 수집

- 신규 `my_tasks.py`에서 개인 업무 조회·분류를 담당한다. 입력은 인증 사용자와 기준 시각, 출력은 구조화된 업무·분류 건수·조회 상태다.
- `outline.py`에 사용자 접근 범위의 업무를 읽기 전용으로 수집하는 함수를 추가한다. 프로젝트별 `documents.list`의 모든 페이지를 읽고 본문이 없는 경우에만 `documents.info`로 보완한다.
- `domain`, `criteria`, `human_tasks`의 파서·업무 적격성·담당자 검사를 재사용한다. `projected` 등 기존 로직을 재사용할 때 원문 쓰기 부작용이 없는지 확인한다.
- `sync`, `normalize`, 업무 목록 생성 함수는 호출하지 않는다. 조회가 업무 상태·완료 체크·원문을 저장하는 계기가 되어서는 안 된다.
- 초판은 현재 원문을 읽는 방식을 기준으로 한다. 기존 로컬 사본만으로 최신이라고 말하거나 RAG 검색 상위 결과로 전체 업무를 대체하지 않는다.
- 요청 안에서 프로젝트·사용자·권한·같은 문서 조회를 재사용한다. LLM·RAG 호출은 0회다.
- 요청별 전체 소요 시간, 프로젝트 수, 문서 조회 수, 부분 실패 수를 기존 계측에 기록한다. 업무 본문은 성능 로그에 기록하지 않는다.

### 실패와 페이지 이동

- 모든 프로젝트를 확인한 경우에만 ‘전체’ 또는 ‘할 일이 없어요’로 확정한다.
- 일부 프로젝트 조회 실패 시 성공한 결과를 표시하되 `일부 프로젝트를 확인하지 못했어요. 조회된 업무만 표시합니다.`와 재시도 버튼을 제공한다. 전체 실패는 빈 업무 목록으로 처리하지 않는다.
- 문서 형식 오류로 본인 배정 여부를 판정할 수 없는 경우 그 문서를 본인 업무로 단정하지 않는다. 접근이 확인된 범위에서 ‘업무 문서 일부를 확인하지 못함’을 별도 안내한다.
- 권한 확인 실패는 저장된 과거 내용을 대신 노출하는 방식으로 복구하지 않는다.
- 페이지·필터 상태에는 사용자·대화방·조회 ID와 문서 ID 순서를 연결한다. 업무 내용의 별도 영구 DB는 만들지 않는다. 조회 메타데이터는 기존 저장소를 쓰고 30분 뒤 만료 처리한다.
- 페이지 이동 때 현재 권한을 확인하고 표시할 문서의 담당자·상태를 재검증한다. 삭제·이동·배정·상태 변화 또는 날짜 변경을 발견하면 전체 목록을 다시 수집하고 `업무가 변경되어 목록을 새로 불러왔어요.`로 알린다.
- 새 업무처럼 기존 페이지 ID로 감지할 수 없는 변경은 `새로고침` 또는 `내 업무` 재입력으로 반영한다. 페이지 이동은 최초 조회 시점의 전체 목록 탐색임을 조회 시각으로 명확히 한다.
- 오래된 버튼은 다른 문서로 다시 연결하지 않는다. 만료·접근 불가 시 최신 목록으로 안내한다.

## 6. 기존 보고 흐름과의 연결

- `내 업무`는 전체 개인 목록, `업무`는 선택 프로젝트의 기존 보고 업무 선택, `현재 업무`는 기존 선택 업무·기준 조회로 역할을 분리한다.
- 새 조회 명령·필터·상세·페이지 버튼은 일반 보고문 처리보다 먼저 해석한다. 버튼 종류는 `my-tasks` 등 독립된 종류로 구분한다.
- 목록·상세 조회는 기존 `reportId`, `editingReport`, 선택 프로젝트·업무를 바꾸지 않는다. 단순 상세 열람이 다음 보고의 대상을 강제로 바꾸면 안 된다.
- 새 목록을 열 때 기존 숫자 메뉴 연결을 정리한다. 숫자 입력은 현재 보이는 업무만 가리키고, 과거 보고 채널 선택 숫자로 잘못 해석되지 않게 한다.
- 기존 보고 초안이 있으면 `보고 현황`으로 돌아가는 버튼을 제공한다. 초안을 조회 동작 때문에 취소·수정하지 않는다.
- 일반 안내에는 `보고` 진입 버튼과 입력 예시를 제공한다. 이후 기존 통합 보고 초안 → 보고 및 반영 → 채널 선택 흐름을 재사용한다.
- 보고 저장 결과 화면에 `내 업무 다시 보기`를 추가한다. 실제로 반영된 기준만 조회에 반영하고, 초안·채팅 게시만 끝난 상태를 업무 완료로 처리하지 않는다.

## 7. 구현 순서와 수정 파일

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | `my_tasks.py` 및 읽기 전용 수집 함수, 담당자·완료·날짜 분류 구현 | 여러 프로젝트와 공동 업무에서 본인 할 일을 정확히 수집하고 원문 쓰기·AI 호출이 0회 |
| 2 | 신규 `my_tasks_chat.py`에 목록·상세·분류·페이지 표시 구현, `chat_ui`의 버튼 연결 재사용 | 짧은 목록부터 긴 제목·다량 기준까지 내용 누락 없이 탐색 가능 |
| 3 | `bot.py` 라우팅, `report_chat.py` 안내·결과 버튼 연결 | 프로젝트 선택 없이 동작하고 기존 보고 초안·편집·채널 선택 유지 |
| 4 | 실패·만료·재조회·권한 변경 처리와 회귀 테스트 | 부분 실패를 전체 성공처럼 표시하지 않고 오래된 버튼이 오작동하지 않음 |
| 5 | 로컬 실행본 적용 및 실제 채팅 확인, 안내 문서 갱신 | 실제 Rocket.Chat에서 가독성과 조회→보고→재조회 흐름 검증 완료 |

추가 테스트 파일은 `test_my_tasks.py`, `test_my_tasks_chat.py`를 기본으로 한다. 기존 보고·권한·버튼 테스트는 필요한 사례만 보강한다. 기능 완료 기록은 이 문서 마지막에 누적하고 측정값·화면은 `reports/`에 보관한다. 서버 전달용 배포 묶음 갱신 여부와 로컬 적용 여부를 구분하여 기록한다.

## 8. 검증 시나리오와 출시 판단

1. 서로 다른 3개 이상 프로젝트의 본인 업무, 타인 업무, 기준 없는 업무, 공동 업무, 관리자 본인 조회를 함께 검증한다.
2. 어제·오늘·내일 마감, 마감일 미정, 한국 자정 전후, 다른 연도의 마감, 보류·시작 예정 업무를 검증한다.
3. 내 기준 일부 완료/전부 완료, 다른 사람만 미완료, 본인 담당 기준 없는 대표 담당자, Outline에서 직접 체크 변경을 검증한다.
4. 100개를 넘는 문서 API 페이지와 8개를 넘는 채팅 페이지, 한 업무의 기준 40개, 같은 이름의 다른 프로젝트 업무를 검증한다.
5. 조회 중 일부 프로젝트 장애, 본문 누락, 문서 형식 오류, 전체 실패를 검증한다. 정상 0건과 구분되어야 한다.
6. 다음 페이지·상세를 누르기 전 권한 회수, 담당자 변경, 프로젝트 연결 해제, 문서 삭제·이동 시 내용이 새로 노출되지 않는지 검증한다.
7. 사용자·대화방이 다른 버튼, 만료 버튼, 과거 숫자 메뉴, 오래된 같은 이름 버튼이 잘못된 보고나 조회로 이어지지 않는지 검증한다.
8. 보고 초안 작성·수정·채널 선택 중 `내 업무`를 열고 돌아와도 초안 내용·버전·선택 문맥이 유지되는지 검증한다.
9. `내 업무 → 작업 내용 보고 → 실제 문서 반영 → 내 업무 다시 보기`에서 완료 기준과 건수가 갱신되는지 검증한다. 일부 저장 실패는 성공한 업무만 달라져야 한다.
10. 신규 테스트 후 기존 채팅 UI·보고 UI·범위·제출·복구·취소·권한 관련 회귀 테스트를 실행한다. 테스트 계정·분리된 데이터로 검증한다.
11. 실제 Rocket.Chat의 일반 폭과 좁은 폭에서 줄바꿈, 버튼, 긴 제목, 상세·다음 페이지, 원문 링크를 확인한다. 원문 쓰기와 LLM·RAG 호출 0회를 계측·테스트로 확인한다.
12. 대표 데이터에서 조회 대기와 출력 시간을 측정한다. 기존 봇의 단일 처리 대기열 때문에 다른 보고 작업을 기다릴 수 있다는 한계도 별도로 기록한다. 이번 기능이 AI를 호출하지 않는 것을 봇 전체 대기 해소로 표현하지 않는다.

완료 판정: **‘내 업무’ 한 번으로 전체 접근 프로젝트의 남은 본인 업무를 빠짐없이 확인하고, 기한 초과와 마감일 미정을 구분하며, 완료 기준을 읽고 기존 보고 흐름으로 자연스럽게 이어갈 수 있을 것.**

## 9. 구현·검증 완료 기록 — 2026-09-30

- `my_tasks.py`, `my_tasks_chat.py`를 추가하고 `outline.py`의 읽기 전용 원문 수집, `bot.py`의 명령 분기, `report_chat.py`의 안내·결과 버튼을 연결했다.
- 일반 목록 8건/쪽, 남은 기준 3개 미리보기, 상세 기준 8개/쪽으로 구현했다. 번호는 현재 보이는 목록에만 연결된다.
- 계획 대비 단순화: 페이지·필터·상세에서도 전체 접근 범위를 새로 읽는다. 따라서 저장된 문서 ID 목록과 원문의 변경 여부를 비교하는 별도 사본은 만들지 않는다. 메타데이터에는 현재 화면의 조회 ID와 30분 만료만 저장하며, 이전 화면 버튼은 최신 목록을 다시 연다.

### 오늘 마감 아이콘 통일

Rocket.Chat 기본 EmojiOne에는 주황 원이 없어 `🟠`만 운영체제 글꼴로 작게 표시되었다. `ops/configure_my_tasks_emoji.mjs`로 테두리 없는 그라데이션 원형 아이콘을 등록하고 오늘 마감 제목에 `:workhub_orange_circle:`을 사용한다. 다른 원형 이모지와 동일한 24px 렌더링을 사용한다. 새 환경에서는 이 설정 도구를 한 번 실행해야 하며, 생성 원본은 `src/workhub/static/workhub-orange-circle.png`에 저장된다. 기존 채팅 표시 테스트 12개 통과 후 로컬 서비스에 적용했다.

### 더보기와 버튼 정리

- 전체·기한 초과·오늘 마감·예정·마감일 미정·새로고침·보고 현황 이동 버튼을 목록과 상세에서 제거했다. 기존 직접 입력 명령은 유지한다.
- 다음 업무가 있으면 `아직 N건의 업무가 더 있어요`와 **더보기**를 본문 바로 아래, 업무별 상세 버튼보다 먼저 표시한다. 이전/다음 목록 버튼은 제거했다.
- 완료 기준 상세도 다음 기준이 있을 때 본문 바로 아래에 **더보기**를 표시한다. 원문 열기와 목록으로 돌아가기는 유지한다.
- 마지막 페이지와 한 페이지에 들어오는 목록에는 더보기가 없다. 기존 12개 채팅 테스트에서 11건의 업무와 40개 기준을 넘겨 보며 누락·버튼 순서·마지막 페이지를 검증했다.
