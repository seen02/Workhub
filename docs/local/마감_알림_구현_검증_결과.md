# Rocket.Chat 개인 마감 알림

2026-10-12 개발 소스와 로컬 Workhub에 적용했다. **workhub-server-gpu 및 서버 배포 패키지는 변경하지 않았다.**

## 사용 방법

통합 업무 비서와의 Rocket.Chat 개인 대화방에 아래 명령을 입력한다. 설정 화면의 버튼으로도 변경할 수 있다.

| 입력 | 동작 |
|---|---|
| `알림` / `알림 설정` | 현재 설정 확인 |
| `알림 받기` / `알림 켜기` | 정기 마감 알림 받기 |
| `알림 끄기` | 정기 마감 알림 중지 |

기본값은 받기다. 설정은 검증된 SSO subject에 연결해 SQLite에 저장하며 재시작 뒤에도 유지한다. 다른 채널이나 여러 사람이 있는 대화방에서 설정을 바꾸지 못한다.

- 매일 **오전 9시, 한국 시간**에 시작한다. 주말도 포함한다. 2026-10-12 17:15 실제 발송 시험 후 사용자 요청으로 오전 9시로 복원했다.
- 오늘부터 **3일 후까지, 양 끝 날짜를 포함**하고 모든 기한 초과 업무를 함께 보낸다.
- 기존 `내 업무` 조회로 본인에게 남아 있는 업무와 완료 기준을 찾는다. 공동 업무에서 본인 기준을 모두 완료하면 제외한다. 업무 전체 상태가 완료인 경우도 제외한다.
- 날짜가 없거나 4일 이후 마감인 업무는 제외한다. 완료 기준별 기한은 부모 업무의 마감일을 따른다.
- `내 업무`와 같은 날짜 제목·분류별 색상 표시·굵은 번호 제목을 사용한다. 기한 초과, 오늘 마감, 3일 이내 마감 순서로 구분하고 업무명·마감일과 상태·본인 완료 기준 비율·남은 기준을 각각 다른 줄에 표시한다. 기준은 항목별로 최대 3개를 보여주며 각 업무의 마지막 줄에 **문서로 이동** 하이퍼링크를 둔다.
- 업무는 `내 업무`처럼 최대 8개를 표시하고 나머지 건수를 안내한다. 하단의 **내 업무 전체 보기**, **알림 설정** 버튼은 고정 명령이므로 알림 발송만으로 기존 보고 메뉴나 선택 업무가 바뀌지 않는다.
- 대상이 없으면 보내지 않는다. 메시지가 길면 첫 항목들과 나머지 건수를 표시하고 `내 업무` 조회를 안내한다.
- 발송 전에 최신 계정 권한·업무 상태·설정을 다시 확인한다. 업무나 프로젝트 일부를 읽지 못한 경우 발송을 보류하고 재시도한다.

09:00~09:15 동안 30초 간격으로 예약 여부를 확인한다. 같은 사람에게 하루 한 번만 보낸다. 실패는 60초 이상 간격으로 최대 3번 시도한다. 이 시간 안에 재시작하면 SQLite 발송 이력과 실행 임대로 중복 실행을 막는다. 응답 유실은 같은 메시지 ID를 조회해 복구한다. 09:15 이후에는 이전 알림을 몰아서 보내지 않고 다음 날 예약을 기다린다. 따라서 오전 9시에 로컬 서비스와 연결된 인증 서비스가 실행 중이어야 한다.

17:15 시험 이미지 `unified-work-assistant/workhub:deadline-alerts-1715-20261012`에서는 453개 회귀 테스트와 실제 발송이 통과했다. 시간 변경 테스트 (`reports/deadline-alerts-1715-tests-20261012.txt`; 로컬 자료), 실행본 검사 (`reports/deadline-alerts-1715-live-20261012.json`; 로컬 자료)를 참고한다. 시간의 분 단위와 시간 경계를 넘는 재시도 창을 검사했다. 이 버전은 시험 이력이다.

가독성 개선 이미지 `unified-work-assistant/workhub:deadline-alerts-readable-20261012`에서 오전 9시 복원과 메시지 표시 개선을 적용하고 455개 회귀 테스트 (`reports/deadline-alerts-readable-tests-20261012.txt`; 로컬 자료)가 통과했다. 사용자 지정 팀장 계정 `admin@example.com`에 가상 업무 3개로 만든 **마감 알림 예시** 한 건을 실제 개인 대화방으로 전송했다. 예시 발송 결과 (`reports/deadline-alerts-readable-example-20261012.json`; 로컬 자료)를 참고한다.

현재 실행 이미지는 `unified-work-assistant/workhub:deadline-alerts-links-20261012`다. 사용자 후속 요청에 따라 각 업무 하단에 **문서로 이동** 하이퍼링크를 표시하며, 팀장 개인 대화방의 기존 예시 메시지에도 접근 가능한 시연 문서 링크 3개를 연결해 수정했다. 455개 회귀 테스트 (`reports/deadline-alerts-links-tests-20261012.txt`; 로컬 자료), 예시 링크 수정 확인 (`reports/deadline-alerts-links-example-20261012.json`; 로컬 자료)이 통과했다. 실제 업무·계정·보고 초안·번호 메뉴·정기 발송 이력은 보존했고 오전 9시 설정을 유지한다. 적용 도구는 `./ops/apply_deadline_alerts.ps1 -Action Links`이며 복구 자료는 `backups/deadline-alerts-links-20261012`에 있다. 현재 `-Action Rollback`은 오전 9시 가독성 개선 이미지로 돌아간다.

현재 로컬 실행본의 인증 경로를 유지했다. 프로젝트 접근 권한과 활성 SSO 계정 확인에 실패한 사용자에게는 발송하지 않는다. 전역 중지가 필요하면 `WORKHUB_DEADLINE_ALERTS_ENABLED=false`를 사용한다.

## 기존 보고 기능 보존

예약 작업은 별도 스레드에서 실행하며 보고 큐, AI 처리, 보고 잠금, 문서 저장 기능을 호출하지 않는다. 알림 본문에는 원문 링크와 명령 안내를 사용한다. 설정 버튼은 고정 명령이므로 기존 번호 목록이나 버튼 연결을 변경하지 않는다.

`알림` 관련 정확한 명령만 보고 처리 전에 분기한다. `알림 기능 검증 완료` 같은 업무 보고 문장은 기존 보고 경로를 따른다. 보고 초안·선택 업무·보고 버전·개인 업무 조회 세션을 알림 저장에 재사용하지 않는다.

작업 폴더에는 아직 로컬에 적용하지 않은 SSO 변경이 있어 다음 두 이미지를 구분했다.

| 이미지 | 범위 | 테스트 |
|---|---|---|
| `workhub-dev/workhub:deadline-alerts-20261012` | 작업 폴더의 현재 전체 개발 소스 | 495개 통과 |
| `unified-work-assistant/workhub:deadline-alerts-20261012` | 기존 로컬 이미지에 알림 변경만 추가 | 452개 통과 |
| `unified-work-assistant/workhub:deadline-alerts-readable-20261012` | 가독성 개선 버전: 오전 9시·내 업무 스타일·예시 발송 | 455개 통과 |
| `unified-work-assistant/workhub:deadline-alerts-links-20261012` | 현재 로컬 실행본: 오전 9시·업무별 문서로 이동 링크 | 455개 통과 |

로컬 이미지의 `auth.py`, `report_parser.py`, `reports.py`, `report_chat.py` 해시가 변경 전과 동일함을 확인했다. 봇·시작 처리·DB 초기화에 필요한 변경만 이미지의 기존 파일에 적용했다. 개발 폴더의 기존 미반영 변경도 보존했다.

## 검증 근거

- 새 알림 테스트 28개: 한국 시간 경계, D+3 포함/D+4 제외, 모든 기한 초과, 공동 업무 본인 기준 완료, 설정 유지와 DM 제한, 부분 조회 실패, 완료·마감 변경 재확인, 권한 회수, 발송 중 끄기, 최대 재시도, 중복 실행 임대, 응답 유실 복구, 긴 메시지, 기존 번호 메뉴·보고 버튼·초안 보존.
- 알림과 받기/끄기 실행 뒤 실제 보고·제안·권한·양식 로직으로 채팅 게시와 Outline 갱신이 정상 완료되는 통합 테스트를 포함했다. 통신 경계와 DB는 격리된 테스트 데이터를 사용했다.
- 현재 개발 소스 전체 테스트: 495개 결과 (`reports/deadline-alerts-tests-20261012.txt`; 로컬 자료).
- 실제 로컬 이미지 전체 테스트: 452개 결과 (`reports/deadline-alerts-runtime-tests-20261012.txt`; 로컬 자료).
- 읽기 전용 실행본 검사: 검증 JSON (`reports/deadline-alerts-live-20261012.json`; 로컬 자료). 예약 창, 새 테이블, 기본 받기, 봇 연결·상태 갱신, HTTP 상태, 기존 보고 상태 보존, 보고·인증 코드 해시, 예약 스레드 등록을 확인했다.
- Workhub만 재시작했다. 다른 15개 컨테이너와 전체 데이터 마운트는 유지했고 16개 서비스가 정상 실행 중이다.
- 서버 폴더 620개 파일의 목록·크기·수정 시각이 동일하다: 보존 검사 (`reports/deadline-alerts-server-preservation-20261012.json`; 로컬 자료).

최초 일회용 계정 생성·삭제를 포함한 검증은 자동 승인 검토가 차단하여 실행하지 않았다. 이후 사용자가 17:15로 변경해 실제 알림을 받는 시험을 요청했다. 2026-10-12 17:15 예약 작업에서 알림 대상 3명 모두 첫 시도에 발송 완료했다. 새 계정이나 업무를 만들지 않았고, 기존 SSO 사용자와 봇으로 구성된 개인 대화방에 실제 메시지가 존재함을 내용 노출 없이 확인했다. 실제 발송 확인 (`reports/deadline-alerts-1715-delivery-20261012.json`; 로컬 자료)을 참고한다.

## 소스·빌드·복구

- 구현: `src/workhub/deadline_alerts.py`.
- 검증: `src/workhub/test_deadline_alerts.py`, `ops/verify_deadline_alerts_live.py`.
- 현재 개발 소스 빌드: `docker build -f ops/Dockerfile.deadline-alerts-dev -t workhub-dev/workhub:deadline-alerts-20261012 .`
- 기존 로컬 이미지에 이번 변경만 빌드: `docker build -f ops/Dockerfile.deadline-alerts -t unified-work-assistant/workhub:deadline-alerts-20261012 .`
- 로컬 적용 도구: `ops/apply_deadline_alerts.ps1`. 실제 `.local/compose.json`에서 Workhub 이미지 값만 바꾸고, 실패하면 이전 이미지로 복구한다. 다른 서비스·서버 패키지를 건드리지 않는다.
- 변경 전 소스·Compose·SQLite와 컨테이너 상태는 `backups/deadline-alerts-20261012`에 보관한다. 인증 정보와 업무 데이터를 포함한 비공개 복구 자료다.
- 이전 로컬 이미지로 복구: `./ops/apply_deadline_alerts.ps1 -Action Rollback`. 알림 설정과 발송 이력은 DB에 보존한다.

메시지 ID 지정은 Rocket.Chat의 [chat.sendMessage](https://developer.rocket.chat/apidocs/send-message), 개인 대화방 생성은 [dm.create](https://developer.rocket.chat/apidocs/create-dm)를 사용한다.
