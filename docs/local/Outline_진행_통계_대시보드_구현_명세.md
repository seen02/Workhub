# Outline 진행 통계 대시보드 구현 명세

- 작성일: 2026-10-01
- 상태: 로컬 구현 및 검증 완료
- 대상: `unified-work-assistant`의 현재 소스와 로컬 실행 환경
- 요청: Outline에 전용 진행 통계 메뉴를 추가하는 방식의 구현 명세 작성
- 독자: 화면 개발자, 서버 개발자, 검증 및 운영 담당자

Outline에서 문서를 읽고 프로젝트를 관리하는 사용자가 같은 서비스 안에서 진행률과 점검할 업무를 확인할 수 있게 한다. 화면은 Outline에 추가하고, 데이터 동기화와 통계 계산은 기존 Workhub를 사용한다. 사용자에게 Workhub 선행 로그인을 요구하지 않는다.

이 문서는 구현 기본값과 완료 판정 기준을 정의한다. 2026-10-01 현재 로컬 서비스에 구현을 적용하고 검증했다. 실제 적용 기능, 검증 근거, 세부 조정 사항과 검증 한계는 [구현 및 검증 결과](Outline_진행_통계_구현_검증_결과.md)에 기록한다.

## 1 목표와 구현 결정

|항목|구현 기본값|
|---|---|
|주 진입점|Outline 왼쪽 메뉴의 `진행 통계`|
|화면 경로|`/workhub/analytics`|

|인증|Outline 로그인 사용자 → Outline 서버 → 서명된 Workhub 내부 요청|
|데이터 원본|Outline에 게시된 업무 문서의 최신 동기화 상태|

|자동 갱신|화면이 보이는 동안 약 20초마다 조회. 동시 요청 중첩 방지|

## 2 현재 코드에서 확인한 기반

경로는 이 문서가 있는 `unified-work-assistant` 기준이다. 작성 시점의 소스를 확인한 내용이며 실행 중 서비스의 동일 버전 적용 여부는 구현 착수 때 별도로 확인한다.

기존 `ANALYTICS-REPORT.md`에는 초기 통계 화면 설명도 남아 있다. 화면 기본값과 제공 기간은 현재 코드의 **관리자 관리 프로젝트 우선, 7일 및 30일**을 기준으로 한다. 실제 집계의 분모와 권한도 현재 코드와 테스트를 우선 확인한다.

Workhub 현재 응답의 문서 범위 검사는 컬렉션 중심이다. Outline 문서별 예외 권한이 업무 열람에 영향을 주는지 착수 단계에서 확인해야 한다. 영향이 있으면 실제 Outline 정책을 이용해 집계 전에 문서를 걸러야 하며, 원문 링크만 차단하고 합계와 제목을 노출하는 방식은 허용하지 않는다.

## 3 구현 범위

### 3.1 첫 적용에 포함할 기능

1. Outline 왼쪽 메뉴와 직접 접근 가능한 전용 화면.
2. 연결된 컬렉션에서 해당 프로젝트의 통계로 이동하는 메뉴.
3. 전체 진행률, 전체 업무, 완료 업무, 미완료, 마감 초과, 마감 임박 카드.
4. 프로젝트별 진행률, 책임자, 완료 업무 수, 마감 초과 비교.
5. 관리자에게 담당자별 완료, 마감 초과, 미완료 현황과 담당자 선택 제공. 일반 직원은 본인으로 고정.
6. 전체 및 완료 업무를 포함한 점검 목록, 검색, 완료 기준 펼치기, 원문 이동.
7. 주간 및 월간 업무 일정, 기간 이동, 날짜 선택, 일정 미설정 업무.
8. 관리자에게 담당자별 일정 겹침 표시. 일반 직원에게 본인 참여 업무 일정 표시.
9. 자동 및 수동 갱신, 갱신 시각, 동기화 지연, 실패 및 빈 화면.
10. 계산 기준과 데이터 오류 안내, 밝은 테마와 어두운 테마, 모바일 및 키보드 사용.

현재 Workhub의 주요 조회 기능을 Outline로 옮긴다. 작업 상태나 일정을 변경하는 동작은 기존 Workhub에서 수행한다. 대시보드 상단에 `Workhub에서 업무 관리` 링크를 제공하며, 특정 업무를 미리 선택하는 링크는 실제 지원 경로가 확인된 경우에만 추가한다.

### 3.2 후속 범위

Outline 안에서 진행 보고 작성 및 확정, 일정 조정, 기준 배정, 주간 현황 생성 및 발행은 별도 명세 대상으로 둔다. 첫 적용에는 새로운 업무 데이터베이스, 새 통계 계산식, AI 진행률 추정, 개인 성과 순위, Workhub 서버 제거를 포함하지 않는다.

서버 전달용 `deployment/` 패키지와 다른 PC의 운영 적용은 로컬 구현 검증 이후 별도 작업으로 수행한다.

## 4 진입과 조회 조건

### 4.1 메뉴와 주소

- 기능 플래그가 켜져 있으면 기존 검색 아래에 `진행 통계`를 배치한다. 공개 공유 페이지에는 표시하지 않는다.
- 현재 계정의 업무 사용자 자격 확인에 성공한 경우 메뉴를 활성화한다. 업무 자격이 없는 계정에는 메뉴를 숨기고 직접 접근 시 이용 자격 안내를 제공한다.
- 자격 확인 서버가 응답하지 않는 경우에는 오류 및 재시도 진입점을 제공한다. 이를 업무 자격 없음으로 단정하지 않는다. 문서 열람은 정상적으로 사용할 수 있어야 한다.
- 연결된 컬렉션 메뉴에서 `진행 통계 보기`를 선택하면 `collectionId`를 지정해 연다. 연결 상태를 확인하지 못하면 미연결로 단정하지 않는다.
- 직접 방문, 새로고침, 뒤로 가기와 앞으로 가기를 지원한다.

예시 주소:

```text
/workhub/analytics
/workhub/analytics?scope=all&collectionId=<UUID>&horizon=7
/workhub/analytics?scope=managed&horizon=30
```

### 4.2 조건과 유지 정책

|조건|동작|
|---|---|
|프로젝트 범위|관리자는 `내가 관리하는 프로젝트`와 `접근 가능한 전체 프로젝트` 선택. 직원은 전체만 제공|
|프로젝트|현재 범위의 연결 프로젝트만 후보로 제공. 컬렉션 진입은 해당 프로젝트를 선택하고 범위는 `all`|
|담당자|관리자는 기본 본인 선택. 팀 전체 또는 다른 담당자로 업무 목록과 일정을 변경하며 상단 지표와 프로젝트 현황은 전체 업무 집계를 유지. 일반 직원은 본인으로 고정하고 선택 UI를 숨김|
|마감 확인 기간|7일 또는 30일. 진행률 자체의 집계 기간을 바꾸지 않음|
|목록 필터|전체 업무, 완료, 미완료, 마감 초과, 마감 임박, 장애요인, 마감일 없음|
|목록 검색|업무명, 프로젝트명, 담당자명 검색. 현재 허용된 응답 범위 안에서만 수행|
|일정 보기|주간 또는 월간, 이전 기간, 다음 기간, 오늘로 이동|

`scope`, `collectionId`, `horizon`은 주소에 유지한다. 담당자, 검색어, 펼침, 일정 위치는 현재 로그인 세션의 화면 상태로 유지하고 주소에는 이메일을 기록하지 않는다. 새 직접 방문은 주소와 사용자별 기본값으로 시작한다. 로그아웃 또는 사용자 및 워크스페이스 변경 시 이전 데이터와 상태를 폐기한다.

프로젝트나 관리 범위를 바꾸면 담당자 조건은 본인으로 돌아간다. 사이드바 `진행 통계`를 다시 누르면 이전 조건을 초기화하고 역할별 기본 프로젝트 범위와 본인 담당자로 돌아간다. 관리자는 이후 팀 전체 또는 다른 담당자를 선택할 수 있다. 직접 입력한 접근 불가 프로젝트 ID는 명시적으로 거부하며 전체 통계로 자동 대체하지 않는다.

관리 프로젝트 범위에 속하지 않는 프로젝트를 명시적으로 지정한 경우 `현재 프로젝트 범위에 포함되지 않습니다.`를 표시하고 `접근 가능한 전체 프로젝트` 전환을 제공한다. 프로젝트 열람 자체의 권한이 없으면 이름이나 책임자를 표시하지 않는다.

## 5 화면 구성과 동작

화면 상단에는 제목, 현재 프로젝트 및 담당자 범위, 마지막 원본 동기화 시각, 새로고침을 표시한다. 그 아래 순서는 핵심 카드, 프로젝트 현황, 점검 업무 및 담당자 현황, 업무 일정, 계산 기준, 조회 조건이다. 관리자와 일반 직원 모두 프로젝트 선택과 마감 확인 기간을 최하단의 `조회 조건` 영역에 배치한다. 관리자의 프로젝트 범위, 담당자, 팀 전체·내 업무 전환도 같은 하단 영역에 둔다. 상단 현재 범위 표시는 유지한다.

```text
진행 통계                         최근 동기화 10:30   [새로고침]

[진행률] [전체 업무] [완료 업무] [미완료] [마감 초과] [마감 임박]

프로젝트 현황
프로젝트명 · 책임자 · 진행률과 막대 · 완료/전체 · 마감 초과

점검할 업무                         담당자 현황
[필터] [검색]                       이름 · 완료 · 초과 · 나머지 미완료
업무명 · 프로젝트 · 담당자
마감 · 남은 기준 · 장애요인 · 다음 행동

업무 일정 [주간 / 월간] [이전] [오늘] [다음]
기간 캘린더 / 마감 초과 / 기간 미설정 / 관리자 일정 겹침

[숫자는 어떻게 계산하나요?]

조회 조건
[프로젝트 범위(관리자)] [프로젝트]
[담당자(관리자)] [팀 전체 / 내 업무(관리자)] [7일 / 30일]
```

### 5.1 핵심 카드와 프로젝트 현황

관리자의 상단 여섯 지표와 프로젝트 현황은 선택한 프로젝트 범위의 열람 가능한 전체 업무를 집계한다. 담당자 기본값이 본인이거나 다른 담당자가 선택되어 있어도 진행률과 프로젝트 현황을 개인 참여 업무로 좁히지 않는다. 관리자 진행률 제목은 `전체 진행률`, 특정 프로젝트에서는 `프로젝트 진행률`이다. 담당자 조건은 점검 업무와 일정에 적용한다.

진행률은 프로젝트 현황으로 이동한다. 나머지 카드 클릭은 해당 업무 목록을 열거나 필터를 변경한다. 관리자는 집계 건수와 목록을 일치시키도록 담당자를 팀 전체로 전환한 뒤 해당 조건을 연다. 프로젝트 행 클릭은 그 프로젝트로 좁히고 `전체 프로젝트`로 복귀할 수 있다. 데이터가 없는 진행률에는 `—`를 표시하고 0% 막대로 오해하게 만들지 않는다.

일반 직원의 진행률 설명은 `본인의 참여 업무 기준`으로 표시한다. 이 숫자는 본인 기준만의 완료율이 아니며, 공동 업무 전체의 진행률을 프로젝트 단위로 평균한 값이다. 관리자의 설명은 `선택 프로젝트 범위의 전체 업무 기준`이다.

### 5.2 점검할 업무

목록에는 업무명, 프로젝트, 담당자, 진행률, 마감일, 남은 날짜, 남은 완료 기준 수를 표시한다. 상세 펼침에는 완료 기준별 상태, 장애요인, 다음 행동을 제공한다. 작성된 다음 행동은 그대로 보여주고 자동 안내는 `점검 제안`으로 구분한다.

미완료 목록의 기본 정렬은 기존 집계 결과의 마감 초과, 장애요인, 마감 임박 우선순위와 마감일 및 제목 순서를 따른다. 완료 목록은 기존 프로젝트명, 업무명, ID 순서를 사용한다. 첫 페이지는 20건이며 필터와 검색을 바꾸면 첫 페이지로 돌아간다.

업무명은 해당 Outline 원문을 새 탭으로 연다. 프로젝트 선택이나 카드 클릭은 페이지 이동 대신 대시보드 범위를 변경한다. 새로고침 후 원문이 삭제되거나 권한을 잃으면 그 업무를 목록에서 제거한다.

### 5.3 담당자 현황

완료, 마감 초과, 미완료 중 초과 제외 건수를 구분한다. 공동 업무는 참여자별로 포함하므로 담당자별 합계가 전체 업무 수보다 클 수 있다는 설명을 제공한다.

관리자는 선택한 프로젝트 범위의 현재 구성원을 함께 본다. 담당자를 선택해도 구성원 비교 목록 자체는 유지하며 배정 업무가 없는 구성원은 0건으로 표시한다. 일반 직원에게는 담당자 비교 화면을 표시하지 않고 서버 응답의 담당자 수치와 후보도 본인으로 제한한다. 서버 응답의 `owners_scope`로 이 차이를 명시한다.

### 5.4 업무 일정

기존 일정 규칙을 순수 계산 함수로 분리해 React 화면에서 사용하거나 동등성을 검증해 이전한다. 유효한 시작일과 마감일이 있고 시작일이 마감일보다 늦지 않은 미완료 업무를 기간에 걸쳐 표시한다. 시작일 또는 마감일이 없는 업무는 별도 목록에 표시하고, 시작일이 마감일보다 늦은 경우에는 일정 오류를 표시한다.

관리자는 현재 필터의 미완료 업무를 본다. 일반 직원은 프로젝트 범위 안에서 **본인이 업무 담당자이거나 완료 기준에 참여한 미완료 업무**만 일정에 표시한다. `내 업무 일정`이라고 명시하며 상단 수치와 목록도 본인 참여 범위로 제한한다.

날짜 클릭은 해당 날짜와 겹치는 업무 목록을 연다. 겹침 판정은 시작일과 마감일 양 끝을 포함한다. 관리자의 담당자별 일정 겹침은 업무 담당자를 기준으로 계산하며, 월간 구간은 기존 주별 최대 동시 건수 규칙을 따른다. 이 숫자가 실제 작업 시간이나 과부하 측정이 아님을 표시한다.

날짜 문자열은 날짜로 취급하고 브라우저 시간대에 따라 하루가 이동하지 않게 한다. `오늘`과 마감 초과 판정은 응답의 한국 날짜 `as_of`를 사용한다.

## 6 통계 계산 계약

집계는 기존 `analytics.build`를 공통으로 사용한다. React에서 별도 진행률이나 완료율을 재계산하지 않는다. 일정 배치와 목록 검색은 화면 동작을 위한 계산으로만 사용한다.

|지표|계산 및 표시|
|---|---|
|프로젝트 진행률|진행률이 유효하게 입력된 해당 프로젝트 업무의 단순평균|
|전체 진행률|집계 가능한 프로젝트 진행률의 단순평균. 프로젝트마다 동일 비중|
|전체 업무|현재 사용자와 조건에 허용된 유효 업무 수|
|완료 업무|상태가 `완료`인 유효 업무 수|
|미완료|유효 업무 수에서 완료 업무 수를 뺀 값. 마감 초과 포함|
|업무 완료율|완료 업무 수 ÷ 유효 업무 수. 상단 진행률과 구분|
|평균 업무 진행률|입력된 업무 진행률의 평균. 전체 프로젝트 진행률과 구분|
|완료 기준 달성률|완료 기준 수 ÷ 전체 기준 수. 프로젝트별 비율의 평균이 아님|
|남은 기준|완료가 아닌 기준 수. 담당자 선택 시 그 사람의 기준만 집계|
|마감 초과|한국 날짜의 오늘보다 마감일이 이전인 미완료 업무|
|마감 임박|오늘부터 선택한 7일 또는 30일 후까지 마감인 미완료 업무. 양 끝 포함|
|장애요인|장애요인에 유효한 값이 있는 미완료 업무|
|마감일 없음|유효한 마감일이 없는 미완료 업무|
|일정 분포|초과, 오늘, 내일부터 선택 기간까지, 이후, 마감 미정. 구간은 중복되지 않음|

같은 업무 문서 ID는 최신 상태 한 건으로 센다. 보고 횟수나 확정 전 초안을 업무 수로 세지 않는다. 연결 해제, 삭제, 보관된 프로젝트 및 활성 업무에서 제외된 문서는 집계에서 제외한다. 일반 문서와 개인 초안도 포함하지 않는다.

형식 오류 업무는 유효 분모에서 제외하고, 권한이 있는 오류 문서의 링크와 이유를 표시한다. 완료 기준 없음 및 진행률 미기재 건수도 제공한다. 분모가 없으면 비율은 `null`로 전달하고 `—`로 표시한다. 진행률 미기재를 0%로 채우지 않는다. 반올림은 기존 소수 첫째 자리 half-up 규칙을 유지한다.

담당자 필터는 그 사람이 업무 담당자이거나 완료 기준에 참여한 업무를 선택한다. 업무 상태와 진행률은 공동 업무 전체 기준이며, 완료 기준 달성 및 남은 기준은 선택한 사람 기준이다. 관리자의 상단 지표와 프로젝트 현황은 같은 권한 검사와 업무 스냅샷에서 담당자 필터 없이 별도로 집계한다. 일반 직원에게 이 전체 집계를 반환하지 않는다. 담당자 현황의 관리자 구성원 비교는 5.3의 규칙을 적용한다.

서로 다른 프로젝트의 진행률이 100%, 20%라면 전체 진행률은 60%다. 한 프로젝트에 업무가 많아도 프로젝트 사이의 비중을 늘리지 않는다. 장애요인과 마감 초과는 같은 업무에 동시에 해당할 수 있으므로 카드 합계를 전체 업무 수로 해석하지 않는다.

## 7 서버 구조와 권한

### 7.1 데이터 흐름

```text
Outline React 화면
  → Outline 인증 API
  → 현재 사용자와 팀 확인 및 서버 간 요청 서명
  → Workhub 내부 통계 API
  → 계정 연결 및 현재 자격 확인
  → 연결 프로젝트와 현재 열람 범위 검사
  → 사용자별 업무 필터와 공통 통계 집계
  → Outline API 응답
  → React 화면 표시
```

`main.py`의 `planning_stats` 본문을 신규 `analytics_service.py`의 공통 조회 함수로 옮긴다. 기존 Workhub API와 신규 Outline 내부 API가 같은 함수를 호출한다. `analytics.py`는 입력된 허용 데이터의 계산에 집중하며 기존 응답 필드와 계산식을 유지한다.

Outline 브라우저는 Workhub 공개 API를 직접 호출하지 않는다. 브라우저가 보낸 사용자 ID, 이메일, 관리자 여부, 허용 프로젝트 목록은 신원 정보로 신뢰하지 않는다. 신원은 Outline 서버의 인증 상태에서 구성하고 Workhub는 현재 계정 매핑과 자격을 검증한다.

### 7.2 권한 기준

|행동|필요 조건|
|---|---|
|통계 진입|활성 Outline 사용자이면서 현재 업무 사용자 자격 보유|
|프로젝트 조회|Workhub에 연결되어 있고 Outline에서 해당 사용자에게 열람 허용|
|관리 프로젝트 범위|현재 업무 관리자이면서 본인이 책임자인 열람 가능 프로젝트|
|전체 통계|관리자는 열람 가능한 연결 프로젝트의 합계. 일반 직원은 해당 프로젝트 안의 본인 참여 업무 합계|
|본인 업무 필터|서버가 확인한 계정 이메일로 필터 적용|
|다른 담당자 조회|현재 업무 관리자만 가능하며 열람 가능한 업무 범위 안에서 적용. 일반 직원의 타인 지정은 403|
|수동 동기화|통계 이용 자격. 요청 제한과 공통 동기화 중첩 방지 적용|
|업무 원문 이동|Outline의 현재 문서 열람 정책으로 최종 확인|

Outline 관리자 권한과 업무 관리자 자격은 별개다. 업무 관리자라는 이유로 비공개 컬렉션 접근권을 추가하지 않는다. 그룹 및 직접 권한 변경은 다음 조회에서 재확인하고 계정 정지, 삭제, 업무 자격 회수도 적용한다.

일반 직원의 담당자 미지정 또는 빈 값은 본인으로 강제한다. 조회와 새로고침, 기존 Workhub API에 같은 제한을 적용한다. 공동 업무의 상태와 진행률은 업무 전체 값이지만 기준 상세와 담당자 수치는 본인 것만 반환한다. 구형 `/api/stats`는 관리자 전용으로 제한해 우회를 방지한다.

현재 컬렉션 기반 업무 조회와 실제 문서 정책의 차이가 확인되면 Outline의 배치 권한 검사 코드를 재사용하거나 별도 통계용 내부 검사로 추출한다. 검색 기능 플래그를 켜야만 통계 권한을 확인할 수 있는 종속성은 만들지 않는다. 집계, 후보, 일정, 오류 문서 모두 동일한 허용 데이터에서 생성하며 기존 Workhub API에도 같은 필터를 적용한다.

### 7.3 서명과 응답 보호

기존 HMAC 서명 형식의 HTTP 메서드, 요청 경로, 시각, nonce, 원문 본문 해시를 사용한다. 계정 매핑은 Outline 사용자 ID와 Authentik의 불변 subject를 따른다. 브라우저에 연동 비밀값이나 서비스 API 키를 제공하지 않는다.

기존 `outline_bridge.verify`의 기능 활성화 검사는 통계 플래그를 독립적으로 검사할 수 있도록 확장한다. 프로젝트 관리 및 검색 요청의 기존 검증과 차단을 보존하며 boolean 인자 추가를 반복하는 대신 명시적 기능 구분을 사용한다.

새 `/internal/outline-analytics/` 경로는 공개 프록시에서 차단한다. 조회 응답은 `Cache-Control: no-store`를 적용하며 사용자 사이에 결과를 공유하지 않는다. 날짜, nonce 등의 인증 기록과 동기화 사본 갱신은 내부 처리이며 원본 업무 문서 변경을 발생시키지 않는다.

## 8 API 계약

### 8.1 신규 엔드포인트

|Outline 인증 API|Workhub 내부 API|목적|
|---|---|---|
|`POST /api/workhub.analyticsCapabilities`|`POST /internal/outline-analytics/capabilities`|이용 자격, 업무 관리자 여부, 본인 이름 및 기본 범위|
|`POST /api/workhub.analyticsQuery`|`POST /internal/outline-analytics/query`|조회 조건을 적용한 통계와 허용된 필터 후보|
|`POST /api/workhub.analyticsRefresh`|`POST /internal/outline-analytics/refresh`|원본 동기화 후 같은 조건의 통계 재조회|

조회와 새로고침 입력은 `collectionId` 선택 UUID, `owner` 선택 이메일, `managed` boolean, `horizon` 7 또는 30이다. 미선택 ID와 담당자는 필드를 생략한다. 기본 `managed`는 서버가 확인한 사용자 역할로 결정하고 `horizon` 기본은 7이다. 기존 Workhub API의 1~90일 입력 호환성은 공통 서비스 추출 후에도 유지한다.

브라우저 요청 예시:

```json
{
  "collectionId": "<선택한 컬렉션 UUID>",
  "managed": false,
  "horizon": 7
}
```

서버 간 요청은 위 조건에 `actor.outlineUserId`, `actor.outlineTeamId`를 Outline 서버에서 추가한다. 입력 스키마는 알 수 없는 필드와 신원 위조용 필드를 거부한다. 이메일은 길이 및 형식을 검증하고 정규화한다. 현재 허용된 업무 또는 본인 계정에 대응하지 않는 담당자는 422로 거부하며 다른 프로젝트의 존재를 안내하지 않는다.

### 8.2 응답

Outline 표준 응답 외피 `{ data: ... }`를 사용한다. 통계 내부 구조는 기존 snake_case 필드명을 유지해 두 호출 경로의 계산 결과를 직접 비교할 수 있게 한다.

관리자 응답에는 `portfolio: { summary, projects }`를 추가한다. 이 값은 현재 프로젝트 범위의 전체 업무 집계로 상단 카드와 프로젝트 현황에서 사용한다. 기존 `summary`, `projects`, 업무 및 일정 목록은 선택 담당자 조건을 유지한다. 일반 직원 응답에는 `portfolio`를 포함하지 않는다.

|필드|계약|
|---|---|
|`as_of`, `until`, `horizon`, `owner`, `collection_id`, `managed`|서버가 실제 적용한 날짜와 조회 조건|
|`summary`|기존 `analytics.build`의 집계 필드 전체|
|`projects`|현재 조건의 프로젝트별 집계|
|`owners`, `owners_scope`|담당자 집계와 관리자 구성원 비교 여부|
|`actions`, `completed_tasks`|미완료 및 완료 업무. 문서 ID, 표시 제목, 원문 URL, 기준, 일정 포함|
|`calendar_actions`|일반 직원의 본인 참여 미완료 업무. 관리자 일정은 `actions` 사용|
|`schedule`|기존 마감 분포|
|`invalid_tasks`|허용된 오류 업무 목록|
|`owner_options`|현재 조회 가능 범위의 담당자 후보와 이름|
|`filter_options.projects`|프로젝트 선택 후보. 단일 프로젝트 선택 시에도 현재 범위의 다른 허용 프로젝트 포함|
|`viewer`|본인 표시 이름, 본인 이메일, 업무 관리자 여부. capabilities와 같은 서버 판정|
|`sync.at`, `sync.ok`|마지막 원본 동기화 시각 및 성공 여부. 없으면 확인 전|
|`generated_at`|통계 응답을 생성한 시각. 원본 동기화 시각과 구분|

위 목록에서 `filter_options`, `viewer`, `generated_at`는 추가 계약이다. 기존 필드의 상세형은 현재 반환값을 기준으로 TypeScript 인터페이스에 명시하고 무형식 객체로 처리하지 않는다. 기존 업무 문서 본문 전체나 인증 설정은 응답에 포함하지 않는다.

필터 후보와 집계는 같은 요청의 권한 스냅샷을 사용한다. 원본 사본은 같은 데이터 스냅샷에서 읽는다. 후보와 집계 사이에 권한 검사 결과가 달라져 접근 불가 프로젝트명이 남는 경우를 방지한다.

### 8.3 오류와 제한

|상태|사용자 동작|
|---|---|
|401|데이터 제거 후 Outline 로그인 안내|
|403|데이터 제거 후 현재 이용 자격 또는 열람 권한 안내|
|404|기능 비활성 또는 연결 해제 및 존재하지 않는 대상. 접근 불가 대상의 상세 정보는 제공하지 않음|
|422|조회 조건 오류 안내. 새 조건과 맞지 않는 이전 수치는 숨김|
|429|요청 제한 안내와 재시도 대기. 자동 재요청 폭주 방지|
|503 및 통신 실패|확인 실패 안내. 동일 조건의 기존 데이터 유지는 9절의 규칙에 따름|

조회는 사용자별 분당 60회, 수동 새로고침은 사용자별 분당 6회를 초기 설정으로 둔다. 구현 때 설치 버전의 rate limiter 전략에 맞춰 추가하며 운영 부하를 측정해 조정한다. 통계 요청 제한과 공개 프록시 차단은 각각 필요하다.

조회 제한 시간은 서버 간 15초, 수동 원본 동기화는 60초를 초기값으로 둔다. 프록시와 클라이언트 제한 시간을 이에 맞추고 대기 중에는 추가 제출을 막는다. 시간 초과를 빈 통계나 완료된 갱신으로 표시하지 않는다.

## 9 갱신과 오류 상태

### 9.1 자동 조회

- 화면 표시 중 20초마다 현재 조건을 조회한다. 숨겨진 브라우저 탭과 화면 이탈 시 중지하고 복귀 때 자격과 범위를 재확인한다.
- 하나의 요청이 진행 중이면 같은 화면의 다음 자동 요청은 건너뛴다.
- 조건 변경과 새로고침에는 요청 번호 또는 취소 신호를 사용해 늦게 도착한 이전 응답이 화면을 덮어쓰지 못하게 한다.
- 자동 갱신은 현재 검색, 페이지, 스크롤, 포커스, 펼친 기준, 일정 위치를 유지한다. 삭제된 업무의 펼침만 해제한다.
- 같은 내용은 기존 화면을 유지한다. 화면 전체를 흐리게 하거나 로딩 화면으로 교체하지 않는다.
- 자동 조회 실패는 다음 정상 주기에 재시도하되 요청 제한 응답은 안내된 대기 시간을 따른다.

### 9.2 수동 새로고침

서버에서 이용 자격과 요청 조건을 확인한 뒤 기존 원본 동기화 함수를 호출하고 공통 통계 조회 결과를 반환한다. 동기화는 사용자 간 요청과 기존 자동 동기화 루프가 중첩되지 않게 기존 잠금 및 진행 상태와 통합한다. 진행 중에는 같은 동기화를 추가로 실행하지 않는다.

잠금 정책을 명시하고 공유 서비스의 전체 요청이 긴 원본 동기화에 묶이지 않도록 계정 조회와 외부 호출 위치를 점검한다. 동기화 대기 때문에 60초를 초과하면 503을 반환하고 사용자가 통계를 재조회할 수 있게 한다. 원본은 읽기만 하므로 결과가 불명확한 경우 원본에 중복 쓰기가 발생하지 않는다.

### 9.3 화면 상태

|상태|표시 기준|
|---|---|
|최초 로딩|영역별 로딩 자리 표시. 0건 및 0% 선표시 금지|
|최초 또는 조건 변경 실패|오류 및 재시도. 해당 조건의 통계 내용을 숨김|
|같은 조건의 일시 갱신 실패|이전 데이터와 마지막 확인 시각 유지. 이전 수치임을 명시|
|계정 또는 열람 권한 거부|이전 데이터, 후보, 상세 목록을 즉시 폐기|
|원본 동기화 실패 또는 2분 이상 지연|지연 안내와 마지막 원본 동기화 시각. 정상 최신 데이터로 표시하지 않음|
|연결된 접근 가능 프로젝트 없음|프로젝트가 없음을 안내. 관리자에게 프로젝트 관리 진입 링크|
|프로젝트에 업무 없음|0건 표시. 분모 없는 진행률은 `—`|
|담당 업무 없음|담당자 조건 해제 또는 다른 프로젝트 선택 안내|
|선택 프로젝트 연결 해제 또는 삭제|선택 대상이 더 이상 이용 가능하지 않음을 안내하고 범위 선택 제공|
|자격 및 권한 확인 서버 장애|확인 실패와 재시도. 결과를 0건으로 대체하지 않음|

통신 실패로 유지된 이전 데이터에도 조회 성공 시각을 표시한다. 마지막 정상 권한 확인 이후 2분 동안 확인에 성공하지 못하면 내용을 숨기고 재확인을 요구한다. 이미 보인 데이터의 권한 변경을 즉시 원격 회수할 수는 없으며, 정상 자동 조회에서는 다음 주기에 변경을 반영한다.

## 10 화면 품질과 성능

Outline의 공통 버튼, 입력, 오류 안내, 색상 토큰을 사용한다. 프로젝트별 색은 식별 보조이며 상태는 문구와 수치로도 전달한다. 밝은 테마와 어두운 테마에서 텍스트와 막대를 확인한다.

데스크톱에서는 점검 목록과 담당자 비교를 나란히 표시하고 좁은 화면에서는 한 열로 쌓는다. 390px에서도 전체 페이지에 가로 넘침이 없어야 한다. 월간 일정은 자체 스크롤 영역 또는 모바일 목록을 제공하고 날짜 이동 및 업무 열람을 유지한다.

키보드로 조건 변경, 카드 선택, 원문 열기, 상세 펼침과 접기가 가능해야 한다. 선택 상태와 오류는 보조 기술에 전달하고 자동 갱신마다 전체 표를 재안내하지 않는다. 모션 감소 설정을 따른다.

첫 구현은 기존 전체 응답을 활용하되 목록 DOM은 페이지당 20건으로 제한한다. 서버가 전체 업무를 임의로 잘라낸 뒤 전체 통계처럼 보여주는 동작은 금지한다. 검증용 100건 및 1,000건 데이터에서 권한 조회 시간, 응답 크기, API 지연, 화면 렌더링 시간을 기록한다.

초기 성능 목표는 로컬 정상 상태의 조회 p95 5초 이내, 응답 이후 화면 반영 1초 이내다. 이는 확정된 성능 실적이 아니라 검증 목표다. 목표를 충족하지 못하면 목록의 서버 페이지 처리 또는 배치 권한 조회를 도입하고, 전체 합계와 목록의 스냅샷을 일치시키는 응답 계약을 보완한 뒤 적용한다. 사용자 사이에서 ACL이나 통계 결과를 공유하는 캐시로 해결하지 않는다.

7. 패치 재현과 소스 빌드 후 로컬 실행 환경에 적용하고 원본 및 기존 기능 보존을 대조한다.
8. 구현 및 검증 결과에 적용 이미지, 실제 검증 범위, 성능과 제한, 복구 방법을 기록한다.

필요한 설계 조정은 이유와 완료 기준 변경을 기록한다. 명세 작성 자체는 이후 구현이나 서비스 배포가 완료됐음을 뜻하지 않는다.

|담당자|공동 업무 전체 진행과 본인 기준 집계 구분, 관리자 구성원 목록 유지, 미배정 구성원 0건|
|관리 범위|본인 책임 프로젝트만 관리 범위에 포함. 접근 불가 관리 프로젝트는 제외|
|달력|한국 날짜 경계, 양 끝 날짜, 시작일 및 마감일 누락, 역전 일정, 월 경계와 주간 및 월간 이동|
|직원 달력|본인 참여 일정만 표시하며 프로젝트 범위 유지. 타인 조회 및 관리자 선택 UI 없음|
|계정|Outline만 로그인한 업무 관리자와 일반 직원의 정상 조회. 업무 자격 없는 Outline 사용자 차단|
|열람|개발, 운영, 공통 등 분리 권한 계정의 프로젝트, 제목, 수치, 후보 및 오류 문서 범위 검사|
|권한 변경|기존 세션에서 그룹 및 직접 권한 회수, 계정 정지, 업무 자격 회수 후 다음 조회 차단|
|문서 권한|실제 정책상 읽을 수 없는 업무가 있는 경우 제목과 합계에서 모두 제외|
|위조와 직접 접근|actor 위조, 다른 팀, 재사용 nonce, 잘못된 서명, 공개 내부 경로 호출 차단|
|연결 상태|해제, 삭제 및 보관 후 목록과 집계 제거. 예전 직접 주소에서 상세 노출 금지|
|갱신 순서|늦은 이전 조건 응답 무시, 자동 조회 중 수동 요청 처리, 숨김 탭 중지, 복귀 재확인|
|실패 화면|초기 오류, 조건 변경 오류, 동일 조건 일시 오류, 지연 표시, 권한 오류 즉시 폐기, 2분 확인 실패 숨김|
|사용성|키보드, 원문 새 탭, 검색, 페이지 이동, 펼침과 스크롤 유지, 두 테마, 390px 모바일|
|부하|100건 및 1,000건 검증 데이터, 응답 크기와 지연 기록, 사용자 동기화 요청 중첩 방지|
|기존 기능|프로젝트 등록 및 해제, 검색, 보고 작성 및 확정, Workhub 통계의 관련 회귀 검사|

두 실제 화면을 순차 조회하면 원본 동기화나 날짜 변경으로 수치가 달라질 수 있다. 동등성 검증에서는 고정 스냅샷을 사용하고, 실제 서비스 비교에서는 동기화 시각과 업무 ID 및 상태가 같은지 확인한다. 응답 생성 시각 자체의 일치는 요구하지 않는다.

실제 쓰기가 필요한 검증은 식별 가능한 검증 컬렉션에서만 수행한다. 기존 운영 문서의 상태, 일정, 기준을 수치 맞추기용으로 변경하지 않는다. 권한 변경 검증은 검증 계정과 컬렉션으로 수행하고 종료 후 복구한다.

### 12.2 완료 기준

- Outline 로그인만으로 진입하고, 직접 URL과 컬렉션 진입 모두 동작한다.
- 3.1의 조회 기능과 사용자별 기본 범위가 구현된다.
- 두 통계 호출 경로가 같은 공통 서비스와 계산식을 사용하고 동일 입력 비교를 통과한다.
- 현재 계정, 프로젝트 및 필요한 문서 열람 경계가 집계 전에 적용된다.
- 오류, 지연, 권한 회수 및 조건 변경 때 다른 범위나 이전 계정의 수치를 표시하지 않는다.
- 관련 Python 회귀 검사와 신규 서버 검사, Outline 타입 검사 및 변경 파일 lint가 통과한다.
- 실제 계정 및 브라우저 검증, 모바일과 테마 확인, 성능 측정 근거가 남는다.
- 깨끗한 고정 원본에 패치를 적용해 동일 수정본을 재현할 수 있다.
- 로컬 적용 전후 기존 프로젝트 ID, 업무 ID, 문서 내용 및 revision 보존을 대조한다.

## 13 기능 설정과 복구

신규 `OUTLINE_ANALYTICS_ENABLED`를 Outline과 Workhub에 추가한다. 초기 기본값은 false이고 로컬 검증 후 양쪽에 true를 적용한다. `OUTLINE_PROJECT_MANAGEMENT_ENABLED` 및 검색 플래그와 독립적으로 동작해야 한다. 기능 플래그만 브라우저에 공개한다.

기존 `WORKHUB_INTERNAL_URL`, `OUTLINE_WORKHUB_BRIDGE_SECRET`, `OUTLINE_WORKHUB_TEAM_ID`와 계정 연결 기반을 재사용한다. 플래그 불일치는 기능 미활성 안내로 처리하며 다른 기능의 플래그를 자동 변경하지 않는다.

새 영구 업무 테이블은 필요하지 않다. 기존 업무 사본, 서명 nonce 기록, 계정 연결을 사용한다. 화면 조회는 원본 문서를 만들거나 변경하지 않는다. 일정과 업무 상태는 기존 원본 작성 흐름에서 갱신되고 통계는 그 결과를 표시한다.

적용 전 현재 Outline 및 Workhub 이미지와 필요한 실행 설정을 복구 기준으로 보존한다. 장애 시 양쪽 통계 플래그를 false로 전환해 새 메뉴와 API를 비활성화하고 필요하면 이전 이미지로 복귀한다. 통계 화면 추가를 되돌리는 데 DB 초기화나 원본 문서 복원이 필요하지 않아야 한다.

이번 명세의 적용 대상은 현재 로컬 환경이다. 서버 배포 패키지는 별도 시점의 산출물이므로 로컬 검증 후 새 이미지, 패치, 프록시 설정 및 기능 플래그를 포함해 따로 갱신한다.
