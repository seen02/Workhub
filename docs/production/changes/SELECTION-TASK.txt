문서 선택 내용 → 업무 등록 소스 구현 기록 (2026-10-23, Asia/Seoul)

완료 범위
- 로컬: unified-work-assistant의 Outline 및 Workhub 소스.
- VM 배포본: output/outline-authentik의 Outline 및 Workhub 소스.
- 이미지 빌드, 이미지 전송, 원격 VM 접속, Compose up/재시작은 수행하지 않았다.
- 실행 설정(.local/compose.json, VM .env), DB, 데이터 볼륨, 계정/문서 권한은 변경하지 않았다.

사용 흐름
1. 프로젝트와 연결된 컬렉션의 게시 문서에서 일반 텍스트를 드래그한다.
2. 기존 선택 도구 모음 오른쪽의 파란 '업무로 추가'를 누른다.
3. 등록된 업무 목록 ID를 서버에서 확인하고 기존 '새 업무' 창을 연다.
4. 선택한 내용의 첫 유효한 줄을 업무명으로, 전체 선택 내용을 업무 내용으로 미리 채운다.
5. 담당자와 마감일, 필요하면 완료 기준을 입력하여 '업무 추가'를 누른다.
6. 업무 목록 바로 아래에 생성한다. 원문 화면은 유지하고 '업무 열기'를 제공한다.

저장과 권한
- 업무 내용은 편집 가능하며 출처 카드의 원문 발췌는 별도로 보존한다.
- 원문 문서에 글자, 체크박스, 링크, 업무 배지 등을 삽입하지 않는다.
- 새 업무 문서에는 원문 제목/링크, 원문 확인 버전, 등록 시각, 인용 발췌를 저장한다.
- 원문 조회 권한과 대상 컬렉션/업무 목록의 생성 권한을 Outline 서버에서 각각 확인한다.
- 기존 서명 브리지와 Authentik 계정/프로젝트 구성원 검증을 재사용한다.
- 일반 직원의 본인 업무 등록과 업무 관리자 담당자 지정 규칙을 유지한다.
- 같은 프로젝트의 등록된 업무 목록만 사용한다. 조회 시 업무 목록을 자동 생성하지 않는다.
- 저장된 원문과 선택 텍스트/앞뒤 문맥이 일치해야 새 요청을 생성한다.
- 공동 편집으로 위치가 달라졌다면 유일한 문맥 일치를 허용한다. 변경되거나 미저장인 내용은 다시 선택하도록 안내한다.
- 이미 예약된 동일 요청은 원문이 편집되어도 원래 발췌로 복구한다. 현재 조회 권한과 생성 권한은 다시 검사한다.
- 기존 요청 ID/내용 해시/예약 문서 ID로 중복 생성과 응답 유실을 처리한다.
- 출처의 업무 표식/체크박스/완료 기준 제목이 실제 업무 필드로 해석되지 않도록 템플릿 판정을 헤더에 한정했다.
- 기존 일반 새 업무 요청의 내용 해시 호환성을 유지한다.

첫 구현 범위
- 일반 텍스트 및 여러 문단 선택, 최대 10,000자.
- 표 선택, 이미지 단독 선택, 초안/템플릿/휴지통/보관/문서 이력/공개 공유 화면은 제외.
- 원문 링크는 문서를 연다. 선택 영역으로 자동 이동하거나 원문과 업무를 양방향 동기화하지 않는다.
- 서로 다른 프로젝트로 보내기와 여러 업무로 자동 분할하기는 포함하지 않는다.

- app/components/WorkhubTaskCreate/index.tsx: 초기값, 출처 카드, 선택 요청 복구, 대상 목록 갱신.
- server/routes/api/workhubTasks.ts: 선택 등록 컨텍스트, 원문 검증, 예약 요청 상태 조회, 서명 브리지.
- Workhub main.py, task_creation.py: 엄격한 출처 요청 모델/별칭, 등록 대상 조회/복구 상태/출처 저장.
- Workhub domain.py, human_tasks.py 및 관련 호출부: 출처를 업무 헤더로 오인하지 않도록 판정 통일.
- 로컬 main.py/outline.py/project_service.py의 검색/채팅/포털 등 기존 추가 기능은 유지했다.
- 공통 Outline 13개 파일의 로컬/VM 내용이 일치한다. 변경 전에도 이 8개 기존 소스는 동일했다.
- 재현 패치와 upstream.lock.json을 갱신했으며 원본 아카이브에서 83개 파일이 재현된다.
- 새 환경변수/의존성/DB 마이그레이션은 없다. Outline과 Workhub를 함께 적용해야 한다.

로컬 적용 명령 (이번 작업에서는 실행하지 않음)
PowerShell에서:

Set-Location '<workspace>'
$settings = Get-Content .local/compose.json -Raw -Encoding UTF8 | ConvertFrom-Json
$outlineTag = $settings.services.outline.image
$workhubTag = $settings.services.workhub.image

# 기존 이미지에 복구용 이름을 추가한다.
docker image tag $outlineTag unified-work-assistant/outline:before-selection-task-20261023
if ($LASTEXITCODE -ne 0) { throw 'Outline 이전 이미지 보존 실패' }
docker image tag $workhubTag unified-work-assistant/workhub:before-selection-task-20261023
if ($LASTEXITCODE -ne 0) { throw 'Workhub 이전 이미지 보존 실패' }

# 기존 Compose가 참조하는 태그로 두 이미지를 빌드한다. 실행 설정은 수정하지 않는다.
docker build -f ops/Dockerfile.outline-selection-task-local -t $outlineTag integrations/outline
if ($LASTEXITCODE -ne 0) { throw 'Outline 이미지 빌드 실패' }
docker build -f ops/Dockerfile.workhub-selection-task-local -t $workhubTag .
if ($LASTEXITCODE -ne 0) { throw 'Workhub 이미지 빌드 실패' }
docker compose -f compose.yml up -d --no-build
if ($LASTEXITCODE -ne 0) { throw '로컬 서비스 시작 실패' }
docker compose -f compose.yml ps

로컬 Dockerfile 안내
- 새 Outline Dockerfile은 현재 없는 20261006 중간 빌드 이미지를 사용하지 않는다.
- Node 26.3.0 빌드 환경과 잠금 파일로 의존성을 설치하며 기존 task-edit-20261019 실행 이미지를 유지한다.
- 기존 두 task-edit-20261019 실행 이미지가 이 PC에 존재하는 것을 읽기 전용으로 확인했다.
- Outline 실행 사용자는 nodejs, 작업 폴더는 /opt/outline임을 확인했다.
- 첫 Outline 빌드는 Node/시스템 패키지/개발 의존성을 내려받으므로 인터넷 연결이 필요하다.
- VM용 기존 docker/Dockerfile.outline 및 Workhub Dockerfile은 그대로 사용할 수 있다. 이번 작업에서는 빌드/전송하지 않았다.
