선택 도구 모음 버튼 누락 후속 수정 (2026-10-23)

관측
- 로컬의 Outline/Workhub 이미지가 새로 생성되어 실행 중인 것을 확인했다.
- 실행 컨테이너의 이미지 ID와 현재 태그 이미지 ID가 같았다.
- 정적 번들에 업무로 추가 코드가 있고 공개 기능 설정도 true였다.
- 기존 로컬 테스트 계정으로 같은 문서(10월 21일 보고)에 로그인하여 텍스트 선택을 재현했다.
- 선택 도구 모음에 기본 서식 버튼만 있고 업무로 추가 버튼이 DOM에 없는 현상을 확인했다.
- 사용자는 강력 새로고침 후에도 동일하다고 확인했다.

수정
- 문서 등록 동작을 중첩 에디터의 props에서 간접적으로 읽는 연결을 제거했다.
- 문서 범위의 SelectionTaskContext로 도구 모음까지 동작을 직접 공유한다.
- 버튼 표시가 런타임 클래스 instanceof 판정과 클라이언트 읽기 권한 캐시의 엄격한 true 값에 의존하지 않도록 했다.
- Document와 Template 모두 isDraft를 가지므로, Document만 가지는 isArchived 속성으로 타입을 좁히도록 마지막 타입 오류를 수정했다.
- 인증된 실제 문서, 문서 상태, 공개 공유/템플릿 제외 조건은 유지한다.
- 실제 원문 조회 및 대상 생성 권한 검사는 기존 서버 API에서 계속 수행한다.
- 읽기 전용 문단의 간단 HTML 렌더링이 선택 도구 모음을 건너뛰지 않도록 등록 동작이 있을 때 실제 에디터를 렌더링한다.
- 기존 에디터에 추가했던 등록 명령/콜백 prop을 제거하고 버튼 클릭에서 현재 선택의 스냅샷을 직접 전달한다.
- 편집/읽기 화면의 실제 에디터 선택 도구 모음을 마운트해 클릭 동작을 검증한다.
- 문서 동작이 늦게 준비되어도 재선택이나 에디터 재생성 없이 버튼이 나타나는 회귀 테스트를 추가했다.

범위
- 로컬 및 VM 배포용 Outline 공통 파일 16개가 일치한다.
- 재현 패치 목록 86개 파일의 원본 대비 재현을 확인했다.
- Workhub 백엔드, 환경변수, 권한 설정, DB 스키마는 후속 수정에서 변경하지 않았다.
- 기존 실행 컨테이너/이미지에 수정 파일을 주입하거나 이미지를 빌드하지 않았다.
- Compose 실행, VM 전송, 프로젝트 연결, 테스트 업무 생성은 하지 않았다.

검증
- 선택/등록 창/서버 권한/실제 도구 모음 관련 27개 테스트 통과.
- 테스트의 로컬 저장 경로를 작업 폴더 내부 test-storage로 지정하여 서버 플러그인의 기본 저장 경로 생성 오류를 해결했다. 서비스 설정은 변경하지 않았다.
- 최종 테스트 실행은 종료 코드 0이며 처리되지 않은 오류가 없다. 최초 실행 로그는 display-fix-tests-initial.log로 보존했다.
- 공통 수정 파일 16개 Oxlint 및 oxfmt 검사 통과.
- 전체 TypeScript 검사 통과 (종료 코드 0, display-fix-typescript.log에 오류 없음).
- 실행 중인 서비스는 수정 전 버전이며, 수정 후 실제 배포 화면 검증은 사용자가 Outline을 재빌드한 뒤 수행해야 한다.

현재 보고 문서의 등록 위치
- 개인 업무 보고 컬렉션은 현재 Workhub 프로젝트로 등록되어 있지 않고 등록된 업무 목록도 없다.
- 현재 기능은 같은 컬렉션의 등록된 업무 목록으로 생성한다.
- 이 문서에서 등록하려면 해당 컬렉션을 프로젝트로 연결해야 한다. 다른 프로젝트에 생성하는 선택 기능은 이번 범위에 없다.
- 이 연결 상태를 자동으로 바꾸거나 업무 목록을 생성하지 않았다.

로컬 반영 명령 (실행하지 않음, 이번 수정은 Outline만 재빌드)
Set-Location '<workspace>'
$outlineTag = (Get-Content .local/compose.json -Raw -Encoding UTF8 | ConvertFrom-Json).services.outline.image
docker build -f ops/Dockerfile.outline-selection-task-local -t $outlineTag integrations/outline
if ($LASTEXITCODE -ne 0) { throw 'Outline 빌드 실패' }
docker compose -f compose.yml up -d --no-deps --no-build --force-recreate outline

실행 후 Ctrl+Shift+R로 새 자산을 불러오고 문장을 드래그하여 확인한다.
